# M117 — Policy, Permissions & Governance Enforcement Layer

M117 turns governance requirements into executable enforcement decisions.

## Request flow

```text
Request
  ↓
Principal
  ↓
Capability
  ↓
Policy
  ↓
Risk
  ↓
Approval?
  ↓
ALLOW / DENY / ESCALATE
  ↓
Audit Event
```

## Principals

A principal can have:
- identity
- roles
- capabilities
- attributes

Capabilities provide a direct authorization primitive.

## Policies

Policies are versioned and contain explicit rules.

A rule can match:
- action
- resource
- conditions

and produce:
- ALLOW
- DENY
- ESCALATE

The default effect is explicit and should normally be DENY for protected systems.

## Approval workflow

Sensitive operations can require approval.

An approval record tracks:
- operation
- requester
- required approver count
- individual decisions
- status

This makes approval a first-class state rather than a comment in a ticket.

## Separation of duties

A basic separation check prevents the requester from also serving as an approver for operations where independent approval is required.

More advanced organizational policies can add role, organization and conflict constraints.

## Risk classification

Operations can be assigned risk levels.

The reference policy classifies examples such as:
- content generation → MEDIUM
- rendering → MEDIUM
- production release → HIGH
- global policy change → HIGH
- learner-state modification → HIGH

These are reference classifications, not universal requirements.

## Enforcement

Authorization returns a structured decision.

Example:

```text
decision: ESCALATE
reason: APPROVAL_REQUIRED
risk: HIGH
```

The decision can then be written into M116's audit event stream.

## Important boundary

M117 decides whether an operation is authorized under declared policy.

It does not execute the operation.

Execution remains with the production/runtime layers.

## Relationship

M116 records governance decisions as events.

M117 creates the policy and permission enforcement mechanism that produces those decisions.

M100 governance concepts can be represented as versioned executable policies.
