# M163 — Security Enforcement & Identity Runtime Layer

M163 turns the security contracts from earlier governance layers into runtime enforcement boundaries.

## Authentication context

Requests can carry:
- subject identity
- issuer
- tenant
- scopes
- authentication method

Authentication context answers who is making the request; it does not by itself authorize the operation.

## Token validation contract

Tokens have explicit issuer, subject, issue/expiry times, scopes and optional audiences.

```text
Token
 ↓
Issuer / Time / Audience Validation
 ↓
Authentication Context
```

The reference implementation models validation fields; it does not verify JWT signatures or call an identity provider.

## Service identity

Services receive explicit identities and audiences.

A revoked service identity cannot be treated as active by a production enforcement layer.

## Authorization policy

Authorization is expressed separately from authentication:

```text
Subject
   +
Scope
   +
Resource
   +
Action
   ↓
Policy Decision
   ↓
ALLOW / DENY
```

Tenant binding can be required so authorization does not cross tenant boundaries.

## Enforcement point

An enforcement point applies the authorization decision at a service boundary.

The reference policy supports fail-closed behavior: unknown decisions become DENY.

## Tenant isolation

Tenant boundaries compare the caller tenant with the resource tenant.

```text
Caller tenant = A
Resource tenant = A
        ↓
      MATCHED

Caller tenant = A
Resource tenant = B
        ↓
     VIOLATION
```

## Credential rotation

Credential rotation is represented as a lifecycle hook with current/next versions and a scheduled rotation time.

Production secret material remains outside this reference package.

## Security audit events

Security decisions can emit explicit events containing subject, service, decision, resource and reason.

These events complement M155 audit/compliance evidence and M150 telemetry.

## Credential lifecycle

Credentials have identity, type, version, expiry and status.

Expired credentials must not be accepted by production enforcement.

## Relationship

```text
M152 Security Governance
        ↓
M162 API Boundary
        ↓
M163 Runtime Enforcement
        ↓
Service / Workflow
```

M159 supplies message identity.

M160 protects state transitions.

M161 protects workflow progression.

M156 supports recovery.

## Important boundary

This layer does not implement cryptographic verification, an OAuth/OIDC provider, a secrets vault, certificate authority, network policy engine or production IAM service.
