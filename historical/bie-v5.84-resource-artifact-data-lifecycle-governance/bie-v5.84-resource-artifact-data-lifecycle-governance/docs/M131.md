# M131 — Resource, Artifact & Data Lifecycle Governance

M131 governs the lifecycle of artifacts and data created by BIE.

## Ownership

Every governed artifact can have an explicit owner and scope.

Ownership can be transferred through an explicit operation.

## Retention

Retention is policy-driven rather than hard-coded.

Policies can define:
- TTL
- archive-after duration
- whether archived data may later be deleted

The reference implementation evaluates age against these policy values.

## Storage tiers

Artifacts can move between explicit storage tiers:

```text
HOT → WARM → COLD → DEEP_ARCHIVE
```

A policy can restrict which tiers are allowed.

## Lineage

Derived artifacts can point to their parent/source artifacts.

Example:

```text
Book
 ↓
Lesson
 ↓
Scene
 ↓
Render
 ↓
Published Video
```

This dependency graph becomes important for safe cleanup.

## Holds

A legal or operational hold can block deletion.

```text
DELETE requested
       ↓
   Active Hold?
     ↙     ↘
   YES      NO
    ↓        ↓
  BLOCK    Continue
```

The hold reason and type are recorded.

## Dependency-aware garbage collection

An artifact should not be deleted merely because its TTL expired.

Deletion checks:
1. active holds
2. downstream dependencies

If either blocks deletion, the artifact remains retained.

The system can also identify orphan candidates that are not referenced.

## Lifecycle

```text
CREATED
  ↓
ACTIVE
  ↓
ARCHIVED
  ↓
DELETED
```

Lifecycle state is explicit.

## Relationship

M120 provides artifact identity.

M130 provides durable workflows that create and consume artifacts.

M131 governs what happens to those artifacts after creation.

M116 audit should record lifecycle actions.

## Important boundary

Retention policy does not itself establish legal compliance. Actual retention periods, holds and deletion rules must be configured according to the applicable organizational and regulatory requirements.
