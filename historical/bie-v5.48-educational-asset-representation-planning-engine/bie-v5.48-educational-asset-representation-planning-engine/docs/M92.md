# M92 — Educational Asset & Representation Planning Engine

M92 decides how educational content should be represented before renderer-specific production.

## Why this layer exists

The same concept may be represented through:
- text
- diagram
- animation
- simulation
- interactive
- narration
- equation
- table
- chart
- example
- assessment
- mixed representation

M92 prevents the production system from treating every lesson as a text-to-video problem.

## Pedagogical intent

Representation selection starts from the learning purpose.

Supported intents include:
- introduce
- explain
- compare
- visualize
- practice
- predict
- simulate
- recall
- diagnose
- assess
- reinforce
- transfer

## Learner-aware selection

The planner can consider learner needs.

Examples:
- representation gap → change representation
- prediction goal → interactive/predictive representation
- spatial relationship → diagram/animation
- dynamic process → animation/simulation
- symbolic manipulation → equation + guided example

These are planning signals, not hard-coded universal pedagogical laws.

## Candidate ranking

The planner separates:
1. candidate generation
2. candidate scoring
3. candidate ranking
4. requirement validation
5. renderer execution

This keeps the rendering technology replaceable.

## Mixed representations

A learning asset can combine representations.

For example:

`Narration + Animation + Equation + Interactive Check`

The representation plan is therefore not restricted to one output type.

## Production requirements

Requirements can enforce:
- visual representation
- interaction
- accessibility constraints
- format constraints
- timing constraints

Additional requirements can be added without changing the core planner.

## Renderer independence

M92 does not decide whether an animation is produced with Remotion, SVG, Canvas, WebGPU, Blender, or another renderer.

It defines the **representation requirement**.

Renderer selection belongs downstream.

## Relationship

M91 provides source-grounded educational content.

M92 decides how that content should be represented.

M81/M83/M84/M85 and downstream production systems can consume the representation plan.
