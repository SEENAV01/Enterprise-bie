# M175 — API Gateway, Routing & Service-Edge Layer

M175 defines the contract for the external service edge.

## Route registration

Routes bind:
- route ID
- path
- HTTP method
- upstream service
- API version
- enabled state

## API versioning

Reference strategies:

```text
HEADER
PATH
QUERY
MEDIA_TYPE
```

Version selection remains explicit rather than implicit.

## Authentication handoff

The gateway can receive an authentication context and pass an identity reference and scopes downstream.

Reference modes:

```text
BEARER
API_KEY
MTLS
SESSION
```

M163 remains authoritative for authorization.

## Rate-limit integration

The edge can apply a rate-limit contract keyed by identity, tenant or another scope.

Reference algorithms:

```text
TOKEN_BUCKET
FIXED_WINDOW
SLIDING_WINDOW
```

M164 remains authoritative for policy.

## Request/response transformation

Transform contracts can modify or normalize:
- request headers
- response headers
- body representation

Actual transformation engines remain adapter-specific.

## Upstream selection

Reference strategies:

```text
ROUND_ROBIN
LEAST_CONNECTIONS
WEIGHTED
HASH
```

## Health-aware routing

Upstream endpoints can be marked:

```text
HEALTHY
UNHEALTHY
UNKNOWN
```

Only healthy endpoints are routable in the reference contract.

## Retries

Gateway retries can be constrained by:
- maximum attempts
- backoff strategy
- retryable upstream status codes

Retries must be coordinated with M161/M171 semantics to avoid duplicate side effects.

## Circuit breakers

Circuit states:

```text
CLOSED
HALF_OPEN
OPEN
```

The contract currently models whether traffic may pass; runtime adapters implement state transitions.

## Edge observability

M175 emits route-level events with:
- route
- operation
- status
- upstream
- latency

These feed M150.

## Relationship

```text
Client
  ↓
M175 Gateway
  ├── M163 Auth
  ├── M164 Policy / Limits
  ├── M171 Messaging
  └── M161 Services / Workflows
```

M174 supplies runtime configuration and feature flags.

M173 can coordinate gateway configuration ownership.

M170 stores large request/response artifacts when payloads are externalized.

## Important boundary

The reference layer does not implement Envoy, NGINX, Kong, API Gateway products, TLS termination, DNS, service discovery, a production WAF, network routing or actual circuit-breaker infrastructure.

## Next

M176 should build the Service Discovery, Health & Endpoint Registry Layer: service registration, endpoint leases, metadata, health probes, readiness/liveness, zone/region awareness, discovery queries, draining/decommissioning and registry observability.
