# M140 — Workflow Orchestration & DAG Execution Layer

M140 is the execution layer that turns BIE's governed components into runnable workflows.

## DAG

A workflow is represented as nodes and dependency edges.

```text
A ──→ C
B ──→ C
```

C becomes ready only after A and B complete.

## Scheduling

The scheduler receives ready tasks and a concurrency limit.

This provides the foundation for:
- sequential execution
- parallel fan-out
- fan-in after dependencies complete

## Retry and backoff

Tasks can declare a retry policy with:
- maximum attempts
- initial backoff
- multiplier

Retries are bounded.

## Checkpoints

Long-running tasks can write ordered checkpoints.

A latest-checkpoint function allows recovery logic to identify the newest saved state.

## Execution state

Workflow state explicitly tracks:
- pending/planned/running/paused/cancelled states
- completed tasks
- failed tasks
- cancellation

## Task leases

A task lease associates execution ownership with a worker and expiration time.

This provides a foundation for worker failure recovery and duplicate-execution control.

## Idempotency

Tasks can carry idempotency keys so equivalent execution requests can be recognized.

Actual durable deduplication belongs to the production execution store.

## Controls

Workflows support:

```text
PAUSE
RESUME
CANCEL
```

These controls are represented explicitly rather than inferred from process state.

## Relationship

M140 consumes the governed artifacts and policies built by previous layers and provides the runtime orchestration mechanism.

```text
Governed Task
     ↓
DAG
     ↓
Scheduler
     ↓
Worker
     ↓
Checkpoint
     ↓
Evaluation
     ↓
Next Task
```

M134 observes execution.

M130 provides recovery concepts.

M135/M136 govern quality and human decisions.

M137/M138/M139 provide provenance, knowledge and asset inputs.

## Important boundary

The reference implementation defines orchestration data structures and scheduling primitives. It does not implement a distributed durable scheduler, persistent execution database, worker autoscaling or exactly-once execution semantics. Those require production infrastructure.

## Next

M141 should build the Distributed Worker Runtime & Execution Sandbox Layer: worker registration, capabilities, resource requirements, isolation, execution environments, artifact mounts, timeouts, heartbeats, worker health and secure task execution so the DAG engine can dispatch real work reliably.
