# M30 — Visual Asset Resolver + Remotion Scene DSL Compiler

M30 creates the bridge between storyboard planning and deterministic Remotion implementation.

## Asset resolution

A scene may need a diagram, equation, photo, chart, UI element or other visual.

The resolver chooses among:
- book-extracted assets
- book-reconstructed assets
- reusable library assets
- vector-generated assets
- Remotion-native primitives
- external/generated assets

The system prefers source-grounded book assets where appropriate and uses deterministic/vector primitives for diagrams, equations and charts when reconstruction is better.

## License/evidence safety

Book-derived assets retain evidence IDs.

External/library assets with unknown licensing are flagged instead of silently approved.

Generated fallbacks can require review.

## Scene DSL

The Scene DSL is an intermediate representation between pedagogical planning and React/Remotion code.

It contains:
- scene identity
- objective
- narration linkage
- evidence
- audio-driven timing
- assets
- layers
- animation events
- camera slots
- transitions
- sync anchors

## Why an intermediate DSL

Directly asking an LLM to generate large amounts of Remotion code makes consistency, reuse and debugging harder.

Instead:

Storyboard
→ Scene DSL
→ Remotion IR
→ deterministic renderer/code generator

This allows scene plans to be validated before code generation.

## Timing

The DSL hard-requires AUDIO_DRIVEN timing. It does not impose a fixed scene duration.

## Important boundary

M30 still does not produce the final MP4. It creates the deterministic scene specification/IR needed by the renderer.
