# M64 — Pedagogical Planning & Curriculum Graph Engine

M64 converts validated knowledge into a structured learning plan.

## Purpose

Knowing what is true is not the same as knowing how to teach it.

M64 represents the instructional path separately from source ingestion and domain reasoning.

## Core graph

`Concept → prerequisite → concept → learning events → assessment`

The graph is course-level and domain-agnostic.

## Learning objectives

Objectives specify what a learner should be able to do.

They can reference concepts and assessment targets.

## Prerequisites

Prerequisite relationships are explicit graph edges.

A topological ordering is generated where possible.

Cycles are treated as a quality-gate failure because they prevent a straightforward prerequisite sequence.

## Misconceptions

Misconceptions are first-class instructional objects.

They can record:
- the incorrect belief
- intended correction
- evidence references

This allows the planner to intentionally address known learner difficulties.

## Learning events

The system supports typed events such as:
- motivation
- explanation
- visualization
- example
- guided practice
- independent practice
- retrieval
- assessment
- reflection

These are planning primitives, not fixed presentation rules.

## Assessment alignment

Assessment targets reference concepts and skills with explicit success criteria.

This enables later checks such as:

`Objective → Concept → Explanation → Practice → Assessment`

## Sequencing

The course sequence is generated from:
- explicit event order
- concept dependencies
- prerequisite constraints

It does not impose a universal fixed lesson duration.

## Domain independence

Nothing in M64 assumes Physics.

The same graph can represent:
- mathematics
- science
- history
- language
- programming
- professional training
- exam preparation

Domain-specific reasoning remains upstream.
