# M42 — Audio-Cue + Timeline Compiler

M42 converts the narrative specification and actual audio timing into a renderer-neutral timeline.

## Core principle

Audio is the temporal source of truth.

The system does not assume:
- every concept has a fixed duration
- every scene lasts the same amount of time
- narration fits a prebuilt animation

Instead:

audio
→ transcript / word timings
→ semantic cues
→ event synchronization
→ scene boundaries
→ frame timeline

## Inputs

M42 accepts:
- audio duration
- optional word-level timestamps
- optional phrase timestamps
- pauses
- narrative events with semantic anchors

## Cue types

The schema supports:
- word
- phrase
- sentence start/end
- pause
- emphasis
- equation
- highlight
- animation start/end
- scene start/end

## Event synchronization

A narrative event can request a semantic anchor.

Example:

"when the narrator says 'current' → reveal definition"

The compiler searches the transcript timing and assigns the event to the corresponding cue.

Unresolved anchors are preserved and flagged rather than silently moved.

## Scene boundaries

Scene boundaries are generated from synchronized events and the actual audio duration.

They are therefore consequences of the explanation rather than arbitrary preset durations.

## Frame conversion

The timeline remains in seconds plus frame coordinates.

At 30 FPS:

time × FPS → frame

The renderer can therefore consume the same timeline without changing the pedagogical model.

## Renderer-neutral design

M42 does not contain Remotion-specific components.

Its output can later be compiled into:
- Remotion
- another video renderer
- interactive playback
- preview systems

This separation keeps knowledge/pedagogy independent from rendering technology.

## Validation

The compiler checks:
- valid duration
- event ordering
- events within audio bounds
- valid scene boundaries
- unresolved anchors
