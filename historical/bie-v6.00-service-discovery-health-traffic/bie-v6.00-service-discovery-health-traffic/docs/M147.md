# M147 — Service Discovery, Health & Traffic Management Layer

M147 gives BIE's distributed services a way to register, discover and route traffic only to suitable instances.

## Service registration

A service instance records:
- service name
- version
- instance ID
- endpoint
- metadata
- routing weight
- status

## Discovery

Consumers can discover instances by service name and optionally version.

Draining instances are excluded from new discovery results.

## Health

Health probes can represent readiness or other checks.

A healthy/ready state can be used as a routing prerequisite.

```text
Instance
   ↓
Health Probe
   ↓
Healthy?
 ├── NO  → Exclude
 └── YES → Eligible
```

## Routing

Routing policies can specify:
- algorithm
- health requirement

Weighted routing is supported in the reference model.

## Circuit breaker

Repeated failures can transition a circuit:

```text
CLOSED
  ↓ failures
OPEN
  ↓ recovery window / probe
CLOSED
```

An open circuit prevents new calls through the reference `allow` check.

## Traffic draining

Instances can be marked DRAINING so new traffic is not assigned while existing work can finish.

This supports graceful deployment replacement.

## Graceful degradation

A service can declare a fallback target.

This provides the contract for degraded behavior when a dependency is unavailable.

## Relationship

```text
M145 API Gateway
       ↓
M147 Discovery / Routing
       ↓
Healthy Service
       ↓
M144 Events / M140 Workflow
       ↓
M141 Workers
```

M146 can dynamically change routing and traffic policies.

M134 can observe health, latency and circuit state.

## Important boundary

The reference implementation does not implement a distributed registry, DNS, service mesh, production load balancer, active probing scheduler or consensus protocol.

It defines the contracts needed by those infrastructure components.
