# M278 — Canonical BIE Integration Spine

## Why this milestone exists

The preceding BIE work already covers many architectural capabilities, but the audit explicitly identifies the missing proof as **one canonical executable pipeline**, real long-book processing, real model calls, production Remotion integration, rendering, QA/repair and final MP4 delivery.

M278 addresses the first and most important integration gap: one canonical run contract.

## Canonical pipeline

```text
SOURCE
  ↓
UNDERSTAND
  ↓
KNOWLEDGE
  ↓
PLAN
  ↓
SCRIPT
  ↓
SCENE
  ↓
REMOTION
  ↓
RENDER
  ↓
QA
  ↓
PUBLISH
```

Every stage writes a named artifact into one RunContext. Gates prevent silent stage skipping. QA is a hard prerequisite for publishing.

## What is real here

- one executable orchestration spine
- deterministic stage order
- stage events
- stage gates
- artifact traceability
- QA → publish gate
- adapter boundaries
- a minimal Remotion output project
- integration tests

## What is intentionally not claimed

This package does **not** claim that arbitrary books are already understood, that external LLM/TTS/asset APIs are wired, or that production rendering/QA is finished.

Those are the next implementation integrations, not reasons to create another disconnected module.
