# M161 — Workflow Orchestration & Long-Running Process Layer

M161 defines durable workflow contracts for processes that may run across many workers, services and time boundaries.

## Workflow definition

A workflow carries identity, version, tenant context, current state and lifecycle status.

## State machines

Workflow progression is explicit:

```text
START
  ↓ BEGIN
RUNNING
  ↓ FINISH
DONE
```

Transitions not declared by the state machine are rejected.

## Durable checkpoints

A checkpoint stores workflow sequence, state and creation time.

The latest checkpoint provides a recovery point for long-running execution.

M156 recovery can restore workflow execution from checkpoints.

## Timers

Timers allow a workflow to wait until a future fire time without keeping a worker continuously occupied.

## Wait conditions

A workflow can wait for an external condition/event and can optionally define a timeout.

## Saga / compensation

Long-running workflows often cannot use one database transaction across all services.

Saga steps therefore pair forward actions with optional compensations.

```text
Step A → complete
Step B → complete
Step C → FAIL
          ↓
      Compensate
          ↓
        B undo
          ↓
        A undo
```

The reference layer models compensation state but does not execute side effects.

## Cancellation

Cancellation is an explicit workflow request and can be approved or rejected.

## Pause / resume

A workflow can be paused and resumed without changing its identity/version contract.

## Human approval

Approval gates define approvers and a required approval count.

The gate becomes APPROVED once the threshold is reached.

## Deterministic replay

Replay inputs are ordered by workflow sequence to support deterministic reconstruction.

This complements M159 replay and M160 state consistency.

## Relationship

```text
M158 Coordination
       ↓
M159 Eventing
       ↓
M160 State Consistency
       ↓
M161 Workflow Orchestration
       ↓
Long-running Process
```

M150 telemetry supplies correlation.

M151 reliability observes workflow health.

M156 recovery uses checkpoints.

M160 prevents stale state transitions.

## Important boundary

The reference implementation does not execute a production workflow engine, distributed timer service, durable task queue, human identity provider, or compensation side effects.
