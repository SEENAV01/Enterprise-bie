# M274 — AI Model & Inference Orchestration Layer

```text
AI Task
  ↓
Model Registry
  ↓
Capability Matching
  ↓
Policy
 ├── Cost Budget
 └── Latency Limit
  ↓
Model Router
  ↓
Inference Job
  ├── Cache Hit → Return
  └── Execute
       ↓
    Success
       │
       └── Failure → Fallback Model
```

## Model registry
Models are registered by model ID and version with capabilities, provider and unit cost.

## Routing
Only active models matching the required capability are eligible. Cost and preferred-provider constraints can narrow selection.

## Governance
Model versions are explicit and can be deactivated without deleting registry history.

## Policies
Task policies can enforce estimated cost budgets and latency limits before inference starts.

## Inference
Jobs have model/version provenance, prompts, attempts and lifecycle states.

## Fallback
A capability-compatible alternative model can be selected when the primary model fails.

## Caching
Cache keys include model ID, model version and prompt, preventing cross-version result reuse.

## Boundary
M274 defines orchestration contracts. It does not implement a provider-specific API, model weights, GPU scheduler or vector database.
