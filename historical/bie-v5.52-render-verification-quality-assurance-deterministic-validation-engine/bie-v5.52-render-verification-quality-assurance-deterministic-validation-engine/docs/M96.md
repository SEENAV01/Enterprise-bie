# M96 — Render Verification, Quality Assurance & Deterministic Validation Engine

M96 determines whether a produced artifact is acceptable.

## Core principle

A successful render only proves that a renderer produced an artifact.

It does not prove that the artifact is correct.

M96 therefore separates:
- render completion
- validation
- acceptance

## Validation dimensions

The engine supports checks for:
- schema
- provenance
- visual correctness
- audio correctness
- timing
- interaction
- pedagogical alignment
- accessibility
- content correctness
- determinism
- renderer success

## Validation contract

Each asset can define a validation contract with:
- checks
- acceptance policy
- required checks
- review policy

This makes QA machine-readable and repeatable.

## Result states

Checks can return:
- `PASS`
- `FAIL`
- `NEEDS_REVIEW`

The aggregate gate follows the strongest failure state.

If a required check is missing, the asset cannot be accepted.

## Provenance validation

M96 can verify that expected source references are present in the produced artifact.

Generated additions can also require explicit labeling.

This protects the source-grounded boundary established in M90/M91.

## Determinism

Artifacts can be fingerprinted from deterministic metadata.

This enables:
- reproducibility checks
- build comparison
- cache verification
- regression detection

A production implementation can extend this to:
- pixel/hash comparisons
- audio fingerprints
- structural scene comparisons
- semantic equivalence

## Human review

Some properties cannot always be reliably reduced to deterministic checks.

`NEEDS_REVIEW` is therefore a first-class state rather than a hidden failure.

Examples:
- ambiguous visual quality
- nuanced pedagogical quality
- borderline accessibility
- source conflict requiring expert judgment

## Acceptance

Only artifacts passing the quality gate should enter the accepted build graph.

Failed artifacts can return upstream for:
- regeneration
- contract correction
- source retrieval
- representation change
- manual review

## Relationship

M95 selects and orchestrates rendering backends.

M96 verifies their outputs.

M94 can then use acceptance status to decide whether downstream nodes are released.
