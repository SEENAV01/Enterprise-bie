# M191 — Data Lineage, Provenance & Governance Layer

M191 defines vendor-neutral contracts for understanding where data comes from, how it changes, who owns it and how governance is applied.

## Datasets and entities

Datasets are governed resources. Entities provide a finer-grained representation that can belong to a dataset.

## Lineage

Lineage is represented as explicit directed edges:

```text
source → transformation → target
```

Supported reference relationships:

```text
DERIVES_FROM
COPIED_FROM
AGGREGATED_FROM
SPLIT_FROM
```

## Transformations

A transformation records the operation, optional version and actor. Versioning allows lineage to distinguish different transformation definitions.

## Provenance

A provenance claim associates a subject with a source and optional method, timestamp and confidence.

## Ownership and stewardship

Ownership records distinguish the accountable owner from an optional steward and domain.

## Data quality hooks

M191 does not replace a data-quality engine. It provides hooks for checks, metrics and thresholds so quality results can participate in governance.

## Governance rules

Rules apply to a scope and carry a requirement and severity:

```text
LOW
MEDIUM
HIGH
CRITICAL
```

## Audit and observability

Governance events record resource, operation, actor and status. Lineage metrics expose edge counts and operation status.

## Important boundary

M191 does not implement a specific catalog, data warehouse, lineage vendor, governance framework or data-quality product. It defines interoperable contracts for those integrations.
