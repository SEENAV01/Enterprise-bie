# M194 — Transaction, Unit-of-Work & Atomic Commit Abstraction Layer

M194 defines vendor-neutral transaction semantics for atomic business operations.

## Transaction scope

A transaction carries:
- transaction ID
- isolation hint
- optional timeout
- optional idempotency key
- lifecycle status

Isolation hints:

```text
READ_UNCOMMITTED
READ_COMMITTED
REPEATABLE_READ
SERIALIZABLE
```

The underlying persistence implementation remains responsible for enforcing the selected isolation behavior.

## Unit of work

A unit of work groups ordered operations under a transaction.

## Read/write sets

Read and write sets make resource access explicit and enable deterministic conflict detection.

## Prepare / commit / rollback

The lifecycle is:

```text
OPEN → PREPARED → COMMITTED
             ↘ ROLLED_BACK
```

Implementations can map these contracts onto local transactions or distributed coordination protocols.

## Conflict detection

A conflict record identifies the transaction pair, resource and reason.

## Idempotency

An idempotency key is associated with an operation hash and optional result reference. This allows retry-safe integration without embedding a particular storage implementation.

## Savepoints

Savepoints provide named transaction checkpoints.

## Audit and observability

Transaction lifecycle events and metrics record operation status, latency and conflict counts.

## Important boundary

M194 does not implement a database transaction manager, distributed consensus protocol, 2PC coordinator, MVCC engine, or lock manager. It defines the common transaction contract and extension points.
