# M51 — Narration & Audio Synchronization Engine

M51 makes spoken explanation the temporal backbone of the educational video.

## Core principle

**Duration is content-driven.**

There is no fixed runtime target.

If an explanation needs more time to be clear, the timeline expands. If an explanation is concise, the timeline contracts.

## Semantic segmentation

Narration is divided into meaningful units such as:
- definition
- explanation
- comparison
- derivation
- example
- conclusion
- misconception correction

Each segment can reference visual elements.

## Timing

The current implementation provides deterministic timing estimation from speech length and speaking rate.

A production implementation should replace estimated timing with actual TTS alignment metadata:
- word timestamps
- phrase timestamps
- phoneme timestamps where useful

The architecture is intentionally independent of a specific TTS provider.

## Visual synchronization

Visual cues can be anchored to semantic narration segments.

Examples:
- equation appears when a term is introduced
- highlight activates when the narrator emphasizes the concept
- diagram transition begins after a causal statement
- particles start when motion is verbally explained

## Pauses

Pauses are semantic, not uniform.

Useful pauses may occur:
- at sentence boundaries
- between concepts
- before an important result
- around emphasis

The system may expand a pause when comprehension benefits from it.

## Audio contract

The audio track stores:
- voice ID
- sample rate
- channels
- language
- semantic timeline reference

The synchronization layer therefore does not depend on one particular voice provider.

## Quality control

The timeline validates:
- segment overlap
- negative durations
- cue range
- empty timelines

## Critical boundary

M51 does not decide the educational content.

M40/M41/M50 determine what should be taught and assessed.

M51 determines how the spoken explanation becomes a precise temporal structure.

## End-to-end timing

The intended production flow is:

lesson reasoning
→ narration draft
→ TTS
→ real speech timestamps
→ semantic timing
→ visual cue resolution
→ Remotion frames
→ render

This makes audio and animation genuinely synchronized instead of merely placing narration over a prebuilt animation.
