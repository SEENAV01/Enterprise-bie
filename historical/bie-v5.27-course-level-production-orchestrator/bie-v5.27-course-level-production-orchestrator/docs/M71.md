# M71 — Course-Level Production Orchestrator

M71 scales the video-generation architecture from a single scene or lesson to a complete course.

## Course graph

A course is represented as:
`Course → Lessons → Scenes → Artifacts`

Lessons can have explicit dependencies.

The dependency graph is topologically ordered and cycles fail the quality gate.

## Incremental generation

Each artifact can receive a deterministic fingerprint.

If an upstream specification has not changed, its artifact does not need to be regenerated.

This is essential for large books/courses where a small edit should not force a full rebuild.

## Parallel production

Independent ready jobs can be grouped into batches for parallel workers.

The orchestrator does not require a specific compute provider.

## Global continuity

Course-wide style tokens and recurring visual assets can be declared.

Lessons can be checked for style drift.

Continuity can later expand to:
- typography
- color tokens
- camera language
- character identity
- diagram vocabulary
- audio identity

## Manifests

Lesson and artifact manifests provide persistent production metadata.

They can reference:
- dependencies
- source provenance
- fingerprints
- output paths

## Failure recovery

Failures are represented separately from successful artifacts.

Retryable failures can be resubmitted without rebuilding unrelated lessons.

## Non-monolithic architecture

The entire course is not treated as one giant render.

This enables:
- partial regeneration
- parallelism
- caching
- targeted debugging
- lesson-level QA
- resumable production

## Relationship to M70

M70 manages individual render reliability.

M71 orchestrates many M70 jobs into a course-level build.

## Relationship to the complete BIE

The pipeline now spans:

`Source → Knowledge → Evidence → Curriculum → Pedagogy → Interaction → Visuals → Audio/Timing → Scene Code → Render → Course`
