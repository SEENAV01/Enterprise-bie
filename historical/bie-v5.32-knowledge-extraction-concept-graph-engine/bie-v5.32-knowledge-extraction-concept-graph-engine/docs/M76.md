# M76 — Knowledge Extraction & Concept Graph Engine

M76 transforms the canonical source produced by M75 into a structured knowledge representation.

## Extraction targets

The model supports:
- sections
- concepts
- definitions
- entities
- equations
- variables and units
- worked examples
- prerequisites
- typed relationships

## Concept graph

A concept becomes an explicit node.

Relationships are typed, such as:
- `PREREQUISITE_OF`
- `PART_OF`
- `RELATED_TO`
- `CAUSES`
- `DEPENDS_ON`
- `EXAMPLE_OF`
- `USES`
- `CONTRASTS_WITH`

This makes the knowledge usable by downstream planning and reasoning systems.

## Provenance

Extracted objects retain source references.

A production extractor should attach exact page/region references from M75.

Confidence can be attached to extraction records.

Low-confidence extraction should enter review rather than silently becoming canonical knowledge.

## Prerequisites

Prerequisite relationships make the graph pedagogically useful.

For example:

`Charge → prerequisite of → Electric Field`

The graph does not assume that every inferred relationship is correct; relationships should carry evidence/provenance and confidence.

## Equations

Equations are first-class graph artifacts instead of plain text.

They can carry:
- formula representation
- variables
- units
- source references

Future validators can connect these to M74 numerical/unit verification.

## Worked examples

Examples remain structured objects so later pedagogy can decide whether to:
- explain
- animate
- convert to practice
- use as assessment
- reuse from M72

## Domain independence

The engine is deliberately not Physics-specific.

It can represent:
- mathematics
- physics
- chemistry
- biology
- history
- economics
- programming
- technical/professional knowledge

The domain-specific ontology and validators can be plugged into the same graph architecture.

## Relationship to earlier modules

M75 provides the canonical source.

M76 extracts knowledge.

M72 can store validated extracted records for reuse.

M74 can verify claims/equations.

M65 can use prerequisites and relationships for pedagogy.

M67 can use concepts and examples for visual planning.

## Important boundary

Extraction is not validation.

M76 says "this structure was extracted/inferred from the source"; M74 determines whether important claims are sufficiently supported for release.

## Next
