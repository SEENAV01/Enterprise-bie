# M43 — Visual Scene Compiler

M43 converts the renderer-neutral timeline into actual visual scene specifications.

## What M43 decides

For every synchronized event it can specify:
- visual primitive
- content
- layout region
- z-order
- style
- object bindings
- lifecycle
- animation primitive
- animation properties

Supported primitives include:
TEXT, EQUATION, SHAPE, ARROW, ICON, DIAGRAM, CHART, PARTICLE, PATH, GROUP, IMAGE, LABEL, HIGHLIGHT, MASK.

Supported motion primitives include:
APPEAR, FADE, WRITE, DRAW, TRANSFORM, MOVE, SCALE, ROTATE, MORPH, HIGHLIGHT, REVEAL, WIGGLE, TRACE, PULSE.

## Separation from Remotion

M43 is renderer-neutral.

It does not directly generate React or Remotion code. Instead it creates a stable intermediate visual representation.

This is important because the same scene specification can later be rendered by different backends.

## Object lifecycle

Every visual object has a lifecycle tied to an event.

Example:

Narration cue
→ equation object appears
→ equation writes
→ relevant term highlights
→ object remains
→ later object transforms or exits.

This avoids treating an animation as one monolithic command.

## Layout

A default 1920×1080 coordinate system is supplied, but regions are explicit so later renderers can adapt them.

## Animation philosophy

Motion is semantic.

The engine explicitly discourages decorative motion. Animation should communicate:
- sequence
- causality
- transformation
- comparison
- attention
- construction

Complex simultaneous motion is limited by policy to reduce cognitive overload.

## Equations

Equations are structured objects, not plain text. They can reveal by mathematical part and synchronize to narration cues.

## Diagrams

Diagrams contain nodes and semantic edges. The edge relationship is part of the representation so a renderer can animate the actual relationship.

## Accessibility

The scene specification includes:
- captions
- equation descriptions
- diagram descriptions
- safe text area
- contrast checking
