# M186 — Distributed Scheduler & Time/Clock Coordination Layer

M186 defines vendor-neutral scheduling and time coordination contracts.

## Scheduling

A schedule carries:
- schedule ID
- expression
- time zone
- optional start/end bounds

## Clock coordination

Clock samples carry both wall-clock and monotonic values plus uncertainty.

The layer treats uncertainty explicitly instead of assuming all nodes share a perfectly synchronized clock.

## Time zones and DST

Time-zone policy is explicit. DST behavior can be:

```text
STANDARD
SKIP
DUPLICATE
REJECT
```

## Misfires

Reference actions:

```text
SKIP
RUN_ONCE
CATCH_UP
RESCHEDULE
```

A grace period controls when a delayed firing remains eligible.

## Distributed leadership

A scheduler leader carries a term and optional lease boundary. Dispatch records include the leader term so stale leaders can be rejected by the execution layer.

## Recurrence

Reference recurrence types:

```text
CRON
INTERVAL
CALENDAR
```

Recurrence may be bounded by count or end time.

## Calendar windows

Schedules can be constrained to explicit time windows and weekdays.

## Dispatch

A firing becomes a dispatch record before entering M182 job execution.

```text
Schedule
   ↓
Fire Time
   ↓
Dispatch
   ↓
M182 Job
```

## Observability

Scheduler events capture:
- schedule
- operation
- status
- clock skew
- misfire state

These feed M150.

## Relationship

```text
M172 → Scheduling foundations
M173 → Distributed coordination
M182 → Job execution
M183 → Concurrency
M185 → Consistency
M186 → Scheduler / Time coordination
M150 → Scheduler observability
```

## Important boundary

M186 does not implement a specific cron daemon, NTP/PTP service, calendar provider, or distributed consensus algorithm.
