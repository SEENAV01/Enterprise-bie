# M129 — Event Schema Registry, Contract Validation & Evolution

M129 protects the event-driven architecture from accidental contract breakage.

## Schema registry

Event types are registered with explicit schema versions.

```text
REVIEW_APPROVED
 ├── v1
 ├── v2
 └── v3
```

Consumers can declare which versions they accept.

## Validation

Incoming events can be validated against the registered schema before processing.

Invalid events should fail explicitly rather than silently entering the workflow.

## Producer and consumer contracts

A producer contract describes what version it emits.

A consumer contract describes which versions it accepts.

The two contracts can be checked before deployment or during contract tests.

## Compatibility

Schema evolution is classified as:
- backward compatible
- forward compatible
- breaking

The reference implementation focuses on required-field changes as a basic compatibility signal.

Production systems should add type changes, enum changes, nested structures, optionality, semantic compatibility and format rules.

## Breaking changes

When compatibility is breaking, possible migration strategies include:

```text
Old v1
  ↓
Migration
  ↓
New v2
```

or:

```text
Producer
 ├── v1
 └── v2
      ↓
Consumers migrate gradually
```

This is represented as `MIGRATE_OR_DUAL_PUBLISH`.

## Deprecation

Old versions can be explicitly marked deprecated and can point to a replacement version.

This supports controlled retirement rather than sudden removal.

## Contract testing

Sample events can be tested against schemas and accepted consumer versions.

This can become a deployment gate.

## Relationship

M128 established event delivery.

M129 establishes stable event contracts so producers and consumers can evolve independently.

M123 configuration versioning can carry schema/contract policy versions.

M116 audit can record contract migrations and breaking-change approvals.

## Important boundary

Schema compatibility is not the same as semantic compatibility. A schema can remain structurally compatible while its meaning changes. Production governance should therefore combine structural contract checks with semantic contract tests.
