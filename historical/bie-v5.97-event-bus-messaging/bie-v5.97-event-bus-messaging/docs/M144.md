# M144 — Event Bus & Inter-Service Messaging Layer

M144 defines asynchronous communication contracts between BIE services, workflows and workers.

## Events and commands

Events describe facts that happened.

Commands request work.

Both carry correlation and causation identifiers when available.

```text
Request
  ↓ correlation_id
Command
  ↓ causation_id
Event
```

## Topics and subscriptions

Events are published to named topics.

Consumers subscribe to topics with explicit delivery semantics.

The reference model defaults to AT_LEAST_ONCE delivery.

## Acknowledgment

Consumers explicitly acknowledge delivered messages.

Offsets can be associated with acknowledgments.

## Idempotent consumption

Because at-least-once delivery can produce duplicates, consumers can derive a deterministic consumer/event key.

```text
consumer_id + event_id
```

A durable implementation should persist this deduplication state.

## Retry and dead letters

Failed deliveries can be retried up to a configured maximum.

Messages that exhaust retries can move to a dead-letter record with the failure reason and attempt count.

## Replay

Consumers can request replay from a topic offset range.

Replay is useful for:
- rebuilding projections
- recovering consumers
- reprocessing after bug fixes
- auditing event-driven workflows

## Ordering

Messages can be ordered by partition and offset.

Global ordering should not be assumed when multiple partitions are used.

## Relationship

M140 orchestrates workflows.

M141 executes tasks.

M144 allows the services and workers to communicate without tight synchronous coupling.

```text
Scheduler
   ↓ event
Worker
   ↓ event
Artifact Store
   ↓ event
Evaluator
   ↓ event
Human Review
```

M134 can observe event flow using correlation and causation IDs.

M137 can attach event identifiers to provenance records.

## Important boundary

The reference implementation defines messaging contracts and local semantics. It does not implement a durable distributed broker, replication, consumer-group coordination, exactly-once processing or cross-region ordering.

Production deployments can map these contracts to an appropriate message broker.
