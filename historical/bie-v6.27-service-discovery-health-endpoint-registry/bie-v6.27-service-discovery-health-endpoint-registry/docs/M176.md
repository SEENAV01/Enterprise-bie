# M176 — Service Discovery, Health & Endpoint Registry Layer

M176 defines the registry contract used to discover routable service endpoints.

## Service registration

A service registration contains:
- service ID
- name
- version
- metadata
- region
- zone
- registration status

## Endpoint registration

Endpoints contain:
- endpoint ID
- address
- port
- protocol
- metadata
- active state

## Endpoint leases

Endpoints can be associated with a time-bounded lease and ownership epoch.

This allows ephemeral instances to disappear from the registry when their lease expires.

M173 remains the authoritative distributed coordination layer.

## Health

Reference endpoint states:

```text
HEALTHY
UNHEALTHY
UNKNOWN
```

Healthy endpoints are routable in the reference contract.

## Probes

Reference probe types:

```text
READINESS
LIVENESS
STARTUP
```

Readiness controls whether traffic should be sent.

Liveness indicates whether an instance remains alive.

Startup allows slow-starting instances to avoid premature failure handling.

## Metadata

Services and endpoints can carry labels and attributes.

Metadata enables discovery filtering without embedding application-specific routing logic.

## Discovery

Queries can filter by:

```text
service name
version
region
zone
health
```

## Draining

Before shutdown or decommissioning:

```text
ACTIVE
  ↓
DRAINING
  ↓
REMOVED
```

A draining endpoint is not routable in the reference contract.

## Registry

A registry entry combines service, endpoint and current health state.

## Observability

Registry events capture:
- service
- endpoint
- operation
- status
- region
- zone

These feed M150 telemetry.

## Relationship

```text
M175 Gateway
      ↓
M176 Service Discovery
      ↓
Endpoint Registry
      ↓
Service / Worker
```

M173 provides endpoint ownership/lease coordination.

M172 can schedule health probes and lifecycle checks.

M174 supplies registry configuration.

M164 policy can constrain discovery visibility.

M150 receives registry telemetry.

## Important boundary

The reference layer does not implement Consul, Eureka, Kubernetes service discovery, DNS-based discovery, Kubernetes probes, cloud load balancers or a production registry cluster.
