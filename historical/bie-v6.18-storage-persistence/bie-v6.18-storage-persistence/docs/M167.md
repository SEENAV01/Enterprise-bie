# M167 — Storage, Data Model & Persistence Abstraction Layer

M167 separates BIE domain/data contracts from any particular database engine.

## Logical entities

Entities define:
- logical name
- fields
- tenant scope
- optional versioning

The entity model is storage-neutral.

## Repository abstraction

Repositories expose persistence contracts without forcing BIE to depend on SQL, NoSQL or a particular vendor.

A repository declares its entity and consistency expectation.

## Query contracts

Queries express:
- entity
- filters
- sort order
- limit

The reference layer does not prescribe a query language or database optimizer.

## Transactions

Transactions have explicit isolation and lifecycle:

```text
OPEN
 ↓
COMMITTED

or

OPEN
 ↓
ROLLED_BACK
```

The abstraction supports common isolation levels but does not implement a transaction engine.

## Indexes

Indexes describe fields and uniqueness requirements.

They provide a logical optimization/constraint contract to the storage adapter.

## Migrations

Schema changes are versioned:

```text
v1
 ↓
Migration
 ↓
v2
```

Migrations are explicit and auditable rather than implicit runtime mutations.

## Archival

Data can move through storage tiers according to an archival policy.

```text
HOT
 ↓
COLD / ARCHIVE
 ↓
DELETED
```

## Storage lifecycle

Reference states:

```text
ACTIVE ↔ ARCHIVED
ACTIVE → DELETED
ARCHIVED → DELETED
```

Deletion remains subject to M166 privacy/retention controls.

## Consistency

Entities can declare read/write consistency expectations.

This allows adapters to select appropriate storage semantics without leaking vendor details into the domain layer.

## Relationship

```text
M166 Data Protection
        ↓
M167 Persistence Abstraction
        ↓
Repository / Storage Adapter
        ↓
Database / Object Store / Archive
```

M165 supplies key references for encrypted persistence.

M166 supplies classification, retention and deletion constraints.

M160 state integrity and M161 workflow state depend on durable persistence.

## Important boundary

This reference implementation does not implement a database, ORM, SQL engine, distributed transaction coordinator, physical index, object store or backup system.
