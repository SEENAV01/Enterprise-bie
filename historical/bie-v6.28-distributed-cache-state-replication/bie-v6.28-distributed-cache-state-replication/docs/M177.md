# M177 — Distributed Cache & State Replication Layer

M177 defines cache and replicated-state contracts without binding the system to a specific cache engine.

## Cache entries

A cache entry contains:
- key
- value
- TTL
- version
- state

## TTL

TTL can optionally refresh on read.

Expired entries are no longer considered valid cache entries.

## Invalidation

Invalidation supports explicit or version-aware invalidation.

```text
PRESENT
  ↓
INVALIDATION REQUEST
  ↓
INVALIDATED
```

## Consistency

Reference modes:

```text
EVENTUAL
READ_YOUR_WRITES
BOUNDED_STALENESS
STRONG
```

Bounded-staleness contracts may specify a maximum permitted age.

## Cache access patterns

Read:

```text
CACHE_ASIDE
READ_THROUGH
```

Write:

```text
WRITE_THROUGH
WRITE_BEHIND
CACHE_ASIDE
```

These are contracts; runtime adapters implement actual cache behavior.

## Distributed state ownership

A key can have an owner and ownership epoch.

M173 provides the distributed coordination primitives used to safely coordinate ownership.

## Replication

Reference modes:

```text
SYNC
ASYNC
```

Replication configuration can specify replica count and maximum acceptable lag.

## Stale reads

Applications can explicitly allow or reject stale reads and optionally bound the tolerated staleness.

## Observability

Cache events capture:
- key
- operation
- hit/miss or status
- latency
- replication lag

These feed M150.

## Relationship

```text
M173 Coordination
      ↓
M177 Cache / State
   ↙       ↘
M167      M150
Storage   Telemetry
```

M174 supplies cache configuration and feature flags.

M171 can carry invalidation events.

M172 can schedule refresh/warm-up jobs.

## Important boundary

The reference layer does not implement Redis, Memcached, Hazelcast, CDN caches, CRDT engines, database replication or a distributed consensus protocol.
