# M81 — Visual Semantics, Diagram & Animation Grammar Engine

M81 creates an intermediate visual language between educational intent and renderer code.

## Why an intermediate visual language

The system should not jump directly from an LLM prompt to arbitrary animation code.

Instead:

`Teaching intent → visual specification → renderer`

This makes visual generation inspectable, reusable and deterministic.

## Visual primitives

Reference primitives include:
- points
- lines
- arrows
- vectors
- axes
- shapes
- text/labels
- grids
- charts
- equations
- images
- particles
- paths
- groups

The grammar is extensible.

## Semantic relationships

Visual objects can express typed relationships such as:
- spatial position
- connection
- direction
- parallel/perpendicular
- equality
- causation
- dependency
- transformation
- highlight

The relationship is semantic, not merely stylistic.

## Visual state and transitions

Scenes can define states and transitions.

A transition can specify behavior such as:
- move
- transform
- morph
- highlight
- trace
- reveal
- flow

Duration is only a hint at this layer. Final timing belongs to temporal/audio synchronization.

## Layout

Layout constraints are explicit.

Production layout solvers can later satisfy:
- anchors
- alignment
- containment
- spacing
- collision avoidance
- safe areas

## Semantic mapping

A visual primitive can be mapped back to:
- concept
- meaning
- source reference

This prevents decorative graphics from becoming disconnected from the teaching objective.

## Renderer independence

M81 does not generate Remotion code directly.

It produces a renderer-independent visual specification that can later compile to:
- Remotion/React
- SVG
- Canvas/WebGPU
- interactive web components
- other renderers

## Domain independence

The grammar is not Physics-specific.

The same primitives can represent:
- mathematical graphs
- chemical structures
- biological diagrams
- timelines
- maps
- software architecture
- engineering systems

Domain-specific semantic grammars can extend the base language.

## Relationship

M80 selects representations.

M81 specifies their visual semantics and behavior.

The next layer can resolve visual assets, style systems, reusable components and domain-specific visual grammars.

## Next

M82 should build the Asset, Visual Style & Reusable Component Intelligence Engine: manage asset selection/generation, style consistency, reusable visual components, iconography, illustration systems, diagram templates and provenance while preventing visual drift across an entire lesson/course.
