# M9 — Book → BIE → Scene Pipeline

This is the first end-to-end architecture for turning arbitrary book text into structured learning-production data.

## Pipeline

Book/PDF text
→ Book IR
→ What/Why/How/When/Where/Who/Derivation/Application matrix
→ Learning graph
→ Higher-knowledge slots
→ Scene planner
→ Remotion Scene DSL (next integration layer)

## Book IR

Each passage keeps:
- passage ID
- text
- page (when available)
- heading path

Each unit keeps:
- source passages
- question taxonomy
- definitions
- processes
- causes
- time/place
- people/entities
- applications
- higher knowledge
- uncertainty

## Important accuracy boundary

This baseline pipeline does not pretend that regex alone can understand a book. It is a deterministic scaffold and contract.

A production BIE model should replace/augment the classifiers with:
1. document layout parsing
2. section/chunk boundary detection
3. LLM structured extraction with JSON schema
4. evidence spans for every claim
5. contradiction/ambiguity detection
6. prerequisite inference
7. external knowledge retrieval as a separately labelled layer
8. confidence scoring and human-review gates

The system must never silently convert model inference into source-derived fact.

## Higher knowledge

`higher_knowledge` is explicitly marked `EXTERNAL_RESEARCH` when supplied from outside the book. This is where the user's requirement — “what knowledge is based on this book's knowledge even if it is not in the book” — enters the architecture without contaminating the source layer.

## Scene planning

Every question kind maps to a candidate visual strategy:
- what → definition
- why → cause/effect
- how → process
- when → timeline
- where → map/location
- who → entity context
- derivation → equation derivation
- application → real-world application

The production renderer can later replace these candidates with domain-specific visual components.
