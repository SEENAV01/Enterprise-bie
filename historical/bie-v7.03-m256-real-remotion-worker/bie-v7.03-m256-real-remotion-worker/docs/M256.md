# M256 — Real Remotion Worker Execution, Process Management, Render Progress, stdout/stderr Capture & Artifact Verification

```text
M255 Render Run
      ↓
Worker Process Specification
      ↓
Remotion CLI / Worker
      ├── stdout
      ├── stderr
      └── progress events
              ↓
        Artifact Verification
              ↓
          Execution Gate
```

## Process management
The worker produces an explicit process specification for the Remotion render command, working directory and arguments.

## Progress
Frame events are normalized into a percentage and current render status.

## Output capture
stdout/stderr are retained as structured events so failures can be diagnosed instead of reduced to a boolean result.

## Artifact verification
The worker verifies the expected MP4/H.264 artifact contract and records duration metadata supplied by the renderer/probe.

## Important implementation boundary
This package defines the **real worker integration contract and event model**, but the generated runtime still uses a deterministic event-ingestion harness rather than launching an external process during package generation. A deployed worker must connect `create_process_spec` to subprocess/container execution and feed actual Remotion output into `ingest_event`.

## Architecture checkpoint
M253–M256 now cover:

`Scene → React/Remotion → Render Job → Worker → Progress/Logs → MP4 Verification`

The next focus should be production reliability: caching, parallel jobs, resource limits, cancellation, retries, observability and cost controls.
