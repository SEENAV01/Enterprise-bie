# M165 — Secrets, Keys & Certificate Lifecycle Layer

M165 defines contracts for handling credentials and cryptographic resources without placing secret material inside ordinary BIE state.

## Secret references

BIE stores a reference to secret material rather than the material itself.

```text
BIE State
   ↓
Secret Reference
   ↓
Secret Provider
   ↓
Secret Material
```

The reference package deliberately does not contain secret bytes.

## Key metadata

Cryptographic keys are represented by metadata:
- key ID
- version
- algorithm
- usage
- status
- creation time
- expiry

The runtime can determine whether a key version is currently usable.

## Key rotation

Key versions can be transitioned:

```text
v1 ACTIVE
   ↓
v2 NEXT
   ↓
Rotation
   ↓
v2 ACTIVE
```

Production rotation must preserve compatibility during the overlap period where required.

## Certificate lifecycle

Certificates carry subject, issuer, validity interval, version and status.

Validity is checked against the current time.

## Revocation

Revocation records identify the affected resource, type, reason and revocation time.

A production trust layer must reject revoked credentials.

## Key usage policy

Keys can be constrained by:
- allowed cryptographic usage
- allowed services
- tenant binding

This limits accidental or unauthorized key reuse.

## Expiry

Secrets, keys and certificates should have explicit expiry checks.

Expired resources must not be accepted by security-sensitive operations.

## Secure material boundary

The core BIE model stores references/metadata rather than secret material.

```text
BIE
 ↓
REFERENCE
 ↓
Vault / KMS / HSM
 ↓
Material
```

The `material_present` and `exportable` flags make the intended boundary explicit.

## Audit

Security-sensitive actions such as rotation can emit audit events.

This connects to M155 audit/compliance and M163 security enforcement.

## Relationship

```text
M163 Identity / Security
        ↓
M164 Policy
        ↓
M165 Secret / Key Lifecycle
        ↓
Secure Runtime
```

M162 integration adapters can use secret references to access external providers.

M161 workflows can request credentials without owning their material.

## Important boundary

This reference implementation does not implement a vault, KMS, HSM, cryptographic algorithms, certificate authority, JWT signing, TLS termination or secret storage.
