# M153 — Secrets, Key Management & Cryptographic Material Lifecycle Layer

M153 defines how BIE references and governs sensitive material without embedding raw secrets into ordinary workflow state.

## Secret references

A secret is represented by a reference:

```text
secret_id
version
scope
expiry
```

The reference is not the secret value itself.

## Key references

Cryptographic keys carry:
- key ID
- version
- purpose
- algorithm
- lifecycle status

## Lifecycle

Supported states include:

```text
PENDING → ACTIVE → ROTATING → EXPIRED
                         ↓
                      REVOKED
```

Production transitions should be controlled and audited.

## Rotation

Rotation creates a new version before retiring the previous version.

```text
v1 ACTIVE
   ↓
v2 CREATED
   ↓
new operations → v2
   ↓
v1 REVOKED
```

Overlap is supported in the contract because different consumers may migrate at different times.

## Encryption metadata

Encryption metadata records the algorithm, key identity, key version and optional mode.

The encrypted payload itself is intentionally outside this reference contract.

## Signing and verification

Signing metadata identifies the signing key and version.

Verification records can bind a signature to a payload digest and key reference.

The implementation does not perform cryptographic primitives.

## Access policy

Secret access is explicitly governed by subject, action and effect.

M152 remains the broader authorization layer; M153 supplies material-specific access contracts.

## Redaction

Sensitive field names such as secrets, API keys, private keys, passwords and tokens can be replaced before telemetry/logging.

## Revocation

A material version can be explicitly revoked with a timestamp and reason.

## Relationship

```text
M152 Authorization
       ↓
Can service access?
       ↓
M153 Secret Reference
       ↓
Secure Material Store
       ↓
Versioned Key
       ↓
Encrypt / Sign
```

M150 provides telemetry and diagnostic context, but raw secret values must never be emitted into telemetry.

## Important boundary

The reference implementation does not implement a vault, HSM, KMS, OAuth secrets store, cryptographic algorithms, key generation, secure enclave or hardware-backed key storage.

Production deployment must connect these contracts to an appropriate secure material provider.
