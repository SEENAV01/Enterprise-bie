# M103 — Parallel Build, Scheduling & Resource-Aware Orchestration Layer

M103 converts the M102 dependency graph into an executable build plan.

## Ready jobs

A job becomes runnable only when all declared dependencies are complete.

Independent jobs can therefore run concurrently.

## Resource-aware scheduling

Jobs can declare:
- CPU
- GPU
- memory
- tool capacity

The scheduler checks capacity before dispatch.

This prevents simple oversubscription such as launching more GPU-heavy renders than the available GPU capacity.

## Critical path

The scheduler estimates downstream completion pressure from dependency duration.

Critical-path ranking helps prioritize jobs whose delay can delay the final build.

This is a planning heuristic, not a claim of globally optimal scheduling.

## Priority

Explicit priority can override ordinary readiness ordering when multiple runnable jobs compete for resources.

## Tool capacity

A tool can itself be a scarce resource.

Example:

```text
Remotion workers = 8
Blender workers = 2
TTS workers = 4
```

Jobs declare their required capacity and the scheduler dispatches only what fits.

## Parallel build

For a course:

```text
Scene 1 ──┐
Scene 2 ──┤
Scene 3 ──┼──→ Lesson
Scene 4 ──┤
Scene 5 ──┘
```

Independent scenes can render in parallel.

A dependent lesson-level artifact waits until required scenes finish.

## Cost awareness

Job estimates can be combined with pricing information to estimate production cost.

Future schedulers can optimize jointly for:
- completion time
- resource utilization
- cost
- priority
- deadline
- reliability

## Relationship

M102 says **what depends on what**.

M103 decides **what should run now and where**.

M101 provides the execution boundaries for each dispatched job.

M98 records orchestration telemetry.
