# M114 — Versioned Build Manifest & Reproducibility Layer

M114 defines the reproducibility contract for complete builds.

## Build manifest

A manifest can freeze:
- source/input versions
- asset versions
- canonical IR version
- generator version
- renderer version
- dependency versions
- configuration
- policies
- environment information
- random seeds

The manifest is independent of any particular domain.

## Canonical digest

The manifest is serialized canonically and hashed.

This produces a deterministic identity for the declared build inputs.

The digest can be used as:
- build identity
- cache key
- provenance reference
- artifact association

## Reproducibility gate

Required manifest fields can be checked before a build is considered reproducible.

This does not claim that arbitrary external systems are automatically deterministic.

A reproducible build requires the declared inputs and deterministic behavior of the participating tools.

## Dependency lock

Dependencies can be represented in a lock structure with:
- name
- exact version
- source
- integrity information

This reduces “works on my machine” drift.

## Cache

The manifest digest can be used as a content-addressed build cache key.

If the same declared inputs are requested again, a previously produced artifact can potentially be reused after validation.

## Rollback

Release records associate:
- build ID
- artifact references
- manifest digest
- release status

This makes a previous known build an explicit rollback target.

## Important boundary

M114 records and verifies the declared reproducibility inputs.

It does not magically guarantee bit-for-bit reproducibility if:
- a renderer is nondeterministic
- an external API changes
- system-level dependencies are uncontrolled
- timestamps/randomness leak into output

Such factors must be captured or controlled by the environment.

## Relationship

M113 identifies and tracks individual assets.

M114 freezes the complete set of inputs and toolchain information required for a build.

M102–M104 execute the resulting build plan.

M100 governance/provenance can consume the manifest digest as a stable build reference.
