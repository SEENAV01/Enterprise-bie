# M14 — Knowledge Graph, Prerequisites & Higher Knowledge

M14 turns extracted BIE units into a graph that can drive learning and video sequencing.

## Four epistemic layers

### SOURCE_DERIVED
Directly supported by book evidence.

### INFERRED
A relationship reasoned from supported evidence but not explicitly stated.

### EXTERNAL
Knowledge verified outside the book.

### SPECULATIVE
A plausible candidate that has not been adequately verified.

These labels are mandatory. The system must never collapse them into one undifferentiated “knowledge” field.

## Graph

Nodes can represent concepts, laws, processes, entities, equations and applications.

Edges can represent:
- prerequisite_of
- part_of
- causes
- enables
- contrasts_with
- derived_from
- applies_to
- measured_by
- represented_by

Every edge carries provenance, status and confidence.

## Prerequisite inference

Document order is only a candidate signal.
A prerequisite should become trusted only after evidence/semantic validation.
This prevents the common mistake of assuming “appears earlier in the book” means “must be learned first.”

## Higher knowledge

For a book-derived base set A, B, C, the engine can propose D as a higher-knowledge candidate.
D is NOT automatically added to the book's knowledge.
It is queued for external research/verification.

## Learning path

The graph supports:
- prerequisite-aware sequencing
- skipping mastered units
- remediation paths
- alternate routes
- application/transfer branches

## Video impact

The learning graph becomes an input to Scene Planning.
A scene is not generated merely because a paragraph exists; it is generated because a learning role exists in the graph.
