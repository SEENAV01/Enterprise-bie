# M113 — Asset & Media Dependency Registry

M113 provides the canonical identity and lineage layer for every asset used by the system.

## Asset identity

An asset has:
- stable asset ID
- version
- type
- URI/reference
- content hash
- MIME type
- metadata

Version and identity are explicit so a build can refer to an exact artifact.

## Provenance

Provenance can record:
- source references
- creator/generator
- transformations
- creation time

This lets the system explain how a generated asset came into existence.

## Transformations

Transformations are versioned.

Examples:
- resize
- transcode
- localization
- accessibility processing
- renderer lowering
- optimization

A transformation should not erase upstream lineage.

## Relationships

Assets can be related using typed edges.

Examples:

```text
source-text@2
   └── DERIVED_TO → diagram@7

diagram@7
   └── USED_BY → scene@14

scene@14
   └── USED_BY → lesson-video@3
```

The exact relationship vocabulary can expand by domain.

## Integrity

Content hashes provide a stable integrity check for concrete bytes.

An implementation can use hashes for:
- cache keys
- deduplication
- artifact verification
- reproducibility

## Impact analysis

When an asset changes, the registry can traverse dependency relationships to determine affected downstream artifacts.

Example:

```text
Source change
    ↓
Diagram stale
    ↓
Scene stale
    ↓
Lesson video stale
```

This enables incremental rebuilding instead of regenerating an entire course.

## Reproducibility

A production artifact should be reconstructable from:
- exact source versions
- exact generated asset versions
- transformation versions
- generation parameters
- renderer/tool versions
- build identity

M113 stores the asset-side portion of this chain.

## Important boundary

The registry tracks assets and lineage.

It does not itself decide:
- what the learner should learn
- which modality is pedagogically best
- how a job should execute

Those responsibilities remain in M106–M112 and M101–M104.

## Relationship

M112's canonical IR references assets.

M113 gives those assets stable identity, provenance and dependency lineage.

M102 can consume the resulting asset relationships to build production dependencies.
