# M178 — Search, Indexing & Query Execution Layer

M178 defines the search/query contract independently of a specific search engine.

## Index definitions

Indexes describe searchable fields, uniqueness and generation/version.

## Analyzers and tokenization

Reference tokenizers:

```text
STANDARD
WHITESPACE
KEYWORD
```

Filters may be applied after tokenization.

Actual linguistic analysis is adapter-specific.

## Query AST

Queries are represented structurally rather than as raw strings.

Reference nodes include:
- TERM
- BOOLEAN
- QUERY

Boolean operators:

```text
AND
OR
NOT
```

## Filtering

Supported reference operators:

```text
EQ NE GT GTE LT LTE IN PREFIX
```

## Sorting

Fields can be sorted ascending or descending.

## Pagination

Both cursor and offset pagination are modeled.

A query must not use cursor and offset simultaneously.

## Ranking

Reference ranking methods:

```text
BM25
BOOLEAN
CUSTOM
```

Field weights can influence ranking.

## Query consistency

Reference modes:

```text
EVENTUAL
BOUNDED_STALENESS
STRONG
```

Bounded staleness can specify maximum index lag.

## Index lifecycle

```text
BUILDING
ACTIVE
REBUILDING
DRAINING
DELETED
```

Only ACTIVE indexes are queryable in the reference contract.

## Rebuilds

Rebuild operations target a new generation from a source index version.

## Aliases

Aliases decouple query clients from physical index generations and can optionally identify the write target.

## Query plans

A plan records execution stages and estimated cost.

Reference stages may include:

```text
PARSE
FILTER
RANK
SORT
PAGE
```

## Observability

Search events record:
- index
- operation
- status
- latency
- hit count

These feed M150.

## Relationship

```text
M174 Configuration
       ↓
M178 Search
  ↙    ↓     ↘
M167  M161   M150
Data  Domain  Telemetry
```

M177 may cache hot query results or index metadata.

M171 can distribute index-change/invalidation events.

M172 can schedule rebuilds and maintenance.

M164 can govern query authorization and data visibility.

## Important boundary

The reference layer does not implement Elasticsearch, OpenSearch, Solr, Lucene, database-specific indexes, linguistic analyzers, vector search, ANN algorithms or a production query optimizer.
