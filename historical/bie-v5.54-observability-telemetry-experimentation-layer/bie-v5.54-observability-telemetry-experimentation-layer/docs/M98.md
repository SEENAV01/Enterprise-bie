# M98 — Learning/Production Observability, Telemetry & Experimentation Layer

M98 makes the complete system measurable.

## Scope

Telemetry can describe:
- learner events
- content events
- planning events
- generation events
- render events
- validation events
- correction events
- build events
- system events
- experiment events

## Structured events

Events have explicit IDs, types, timestamps, entity references, payloads and context.

This creates a common event language across the pipeline.

## Metrics

Metrics can be derived from event streams or emitted explicitly.

Examples include:
- validation failure rate
- generation success rate
- average render latency
- asset production cost
- correction iterations
- learner progression
- completion rates

M98 does not prescribe which learning metric is universally correct.

## Distributed traces

A trace can connect spans across:
- planning
- generation
- rendering
- validation
- correction

This makes slow or failing production paths diagnosable.

## Cost and latency

Cost and latency are first-class observability dimensions.

This is important because a learning system can be pedagogically strong but economically impractical at scale.

## Experimentation

Experiments contain:
- hypothesis
- variants
- metrics
- allocation

Examples can later compare:
- representation strategies
- explanation styles
- interaction patterns
- rendering strategies
- correction policies

Experiments must not silently alter core semantics.

## Privacy and telemetry boundaries

The reference policy emphasizes:
- collecting only declared events
- minimizing learner identity
- not requiring sensitive data for core metrics
- purpose limitation
- configurable retention
- separation of raw events and aggregates

These are architectural policies, not claims about any particular legal regime.

## Evidence-driven optimization

M98 supplies evidence.

It does not itself decide that a particular representation is better.

Future optimization systems can consume these metrics and feed controlled policy updates upstream.

## Relationship

M96 validates output.

M97 corrects failures.

M98 records what happened across both production and learning.

## Next

M99 should build the Evaluation, Benchmarking & Policy Optimization Layer: define comparable evaluation suites, benchmark representations/renderers/correction strategies, calculate multi-objective quality-cost-latency scores, and produce bounded policy recommendations without allowing uncontrolled self-modification of the core system.
