# M148 — Distributed Locking, Coordination & Leader Election Layer

M148 defines coordination primitives for multiple BIE instances competing for shared resources or singleton work.

## Distributed locks

A lock identifies:
- resource
- owner
- lock ID
- fencing token
- expiry
- status

Locks are time-bounded.

## Leases

Leases provide explicit ownership lifetimes.

An expired lease cannot be treated as active.

## Fencing tokens

Every new ownership generation receives a monotonically increasing token.

```text
Owner A → token 41
Lease expires
Owner B → token 42
```

A stale owner with token 41 can be rejected by a downstream resource currently accepting token 42.

This is the key defense against delayed/stale workers continuing after lease loss.

## Leader election

Candidates can be ranked by term and priority.

The reference election helper selects the highest tuple.

Production systems must obtain election state from a strongly consistent coordination system.

## Coordination state

Compare-and-set semantics prevent updates based on stale versions.

## Ownership

Critical operations can carry:
- resource
- owner
- fencing token
- lease ID

This gives downstream components an explicit ownership proof.

## Singleton workflows

A workflow can have one active ownership record.

```text
Workflow
   ↓
Acquire
   ↓
Lease + Fencing Token
   ↓
Execute
```

A second instance should not execute unless it acquires the newer valid ownership generation.

## Split-brain protection

The model exposes quorum state and stale-owner detection.

A production coordinator should require an appropriate quorum before accepting authoritative writes.

## Relationship

```text
M140 Orchestrator
      ↓
M148 Coordination
      ↓
Lease + Lock + Fencing
      ↓
M141 Worker
      ↓
Shared Resource
```

M147 determines which service instances are healthy.

M146 can govern coordination policies.

M144 can publish leadership/ownership events.

## Important boundary

The reference implementation is a coordination contract model. It does not implement a consensus algorithm, replicated state machine, distributed database, network partition detector or production-grade lock service.

Production deployment must use a strongly consistent coordination substrate and enforce fencing at the resource boundary.
