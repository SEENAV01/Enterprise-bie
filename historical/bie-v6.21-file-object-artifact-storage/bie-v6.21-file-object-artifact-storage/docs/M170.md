# M170 — File, Object & Large-Artifact Storage Layer

M170 provides a storage-neutral contract for files and large artifacts such as videos, datasets, documents and generated assets.

## Object references

BIE stores a logical object reference rather than embedding large binary content in domain state.

A reference may contain:
- object ID
- bucket/container
- key/path
- tenant
- version

## Upload

Uploads have explicit lifecycle:

```text
REQUESTED
   ↓
IN_PROGRESS
   ↓
COMPLETED
```

The abstraction does not dictate the physical object store.

## Download

Downloads can request:
- object version
- optional byte range

This supports large-file and resumable access patterns.

## Multipart transfer

Large uploads can be divided into parts.

```text
Part 1 ─┐
Part 2 ─┼→ Multipart Object
Part N ─┘
```

Each part can have its own checksum/reference.

## Checksums

Reference checksum algorithms:

```text
SHA256
SHA512
MD5
```

Production security policy may restrict algorithms; this layer only models the contract.

## Metadata

Objects can carry:
- content type
- size
- checksum reference
- custom metadata

## Versioning

Objects can maintain versions independently of the domain entity.

```text
v1
 ↓
v2
 ↓
v3 ← CURRENT
```

## Lifecycle

Reference states:

```text
ACTIVE
  ↓
ARCHIVED
  ↓
DELETED
```

Transitions remain subject to retention/privacy policies.

## Quarantine and scanning

New or suspicious objects can enter:

```text
QUARANTINED
    ↓
 RELEASED / REJECTED
```

The scanner is an external hook; M170 does not implement malware/DLP scanning.

## Access control

Object actions include:

```text
READ
WRITE
DELETE
LIST
```

Tenant context and allow/deny decisions are explicit.

M163 authorization remains authoritative.

## Retention

Object deletion can be blocked by:
- retention period
- legal hold

This integrates with M166.

## Relationship

```text
M165 Keys
   ↓
M166 Protection / Retention
   ↓
M170 Object Storage
   ↓
M167 Persistence / M168 Cache
   ↓
M161 Workflows / M162 APIs
```

Generated video/game/course artifacts can use this layer without placing binaries inside workflow state.

## Important boundary

The reference layer does not implement S3/GCS/Azure Blob, multipart transport, malware scanning, CDN delivery, signed URLs, physical deletion or object-store replication.
