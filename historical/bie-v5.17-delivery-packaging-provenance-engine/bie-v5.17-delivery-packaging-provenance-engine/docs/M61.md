# M61 — Delivery Packaging & Provenance Engine

M61 is the final packaging and traceability layer.

## Purpose

A finished video is not enough for a serious production system.

The system should retain enough metadata to answer:

`What was produced, from which inputs, with which versions, under which build, and with which asset rights?`

## Deliverable manifest

The manifest records:
- course identity
- release version
- artifacts
- captions
- accessibility metadata

## Provenance

Each entity can reference:
- source documents
- model versions
- prompt/version references
- build identity

The system records references; it must not fabricate provenance that is unavailable.

## Build reproducibility

A build record can include:
- build ID
- source/git reference
- renderer version
- engine version
- configuration
- deterministic build fingerprint

## Licensing

Assets can carry:
- license
- source URL
- attribution
- restrictions

Missing license metadata is a quality-gate failure.

## Accessibility

The package explicitly declares:
- language
- captions
- transcript
- optional audio description

This creates a machine-readable accessibility contract.

## Captions

Captions are first-class deliverables, not merely an internal rendering artifact.

## Package

The package combines:
- manifest
- provenance
- build record
- license records

under a versioned package format.

## Relationship to previous modules

M60 verified production quality.

M61 records and packages the validated result so that delivery, auditing, revision and reproducibility are possible.

## Important limitation

Provenance is only as accurate as the upstream records. M61 must preserve uncertainty or missing data rather than inventing sources, licenses, prompts or model history.
