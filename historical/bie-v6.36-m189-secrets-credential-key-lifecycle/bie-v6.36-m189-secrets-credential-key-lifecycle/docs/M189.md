# M189 — Secrets, Credential & Key Lifecycle Management Layer

M189 defines vendor-neutral lifecycle contracts for secrets, credentials and cryptographic keys.

## Secret references

The core system stores references to secrets rather than requiring raw secret material in normal application contracts.

A reference can include a version and scope.

## Key records and versions

Keys have explicit algorithm, purpose, version and lifecycle status.

```text
ACTIVE
DISABLED
REVOKED
EXPIRED
```

Historical versions remain addressable so rotation does not require rewriting old references.

## Rotation

A rotation plan records the current and next version and an optional activation time.

```text
v3 → rotation plan → v4
```

## Revocation

Revocation is explicit and carries a reason and timestamp metadata.

## Credential leases

Credentials can be bounded to a principal and validity interval.

## Envelope encryption

M189 models the boundary between a data-key reference and a wrapping-key reference. Raw key material is not embedded in the contract.

## Secure retrieval

Retrieval is an explicit request containing:
- secret reference
- principal
- purpose

The result records the resolved version without exposing the secret in the lifecycle contract.

## Audit

Lifecycle operations generate audit events for rotation, retrieval, revocation and related operations.

## Observability

Key lifecycle events capture key ID, version, operation and status.

## Relationship

```text
M165 → Key / credential foundations
M174 → Configuration
M188 → Identity / Authorization
M189 → Secret / Key Lifecycle
M150 → Security Observability / Audit
```

M188 authorization can gate M189 retrieval requests.

## Important boundary

M189 does not store raw production secrets, implement a specific KMS/HSM, or provide cryptographic primitives. It defines lifecycle and integration contracts for such systems.
