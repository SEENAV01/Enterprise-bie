# M34 — Course / Book Production Orchestrator

M34 upgrades the system from isolated lesson generation to whole-book/course production.

## Global memory

A book-level memory stores:
- canonical terminology
- concept registry
- global visual/style profile

This prevents terminology and presentation style from drifting between chapters.

## Cross-chapter dependency graph

Lessons can depend on lessons from earlier chapters. The production queue respects these dependencies.

A cyclic dependency blocks the queue instead of silently producing an invalid order.

## Reusable asset cache

Assets are indexed by semantic identity, variant and style version.

The same conceptual visual can therefore be reused across many lessons without regenerating it unnecessarily.

## Production policies

The book-level orchestrator preserves:
- cross-chapter consistency
- asset reuse
- audio-driven timing
- incremental generation

## Why this matters

A complete book may contain hundreds of lessons and thousands of scenes. Treating each lesson as an isolated prompt would cause:
- terminology drift
- inconsistent visual grammar
- repeated asset generation
- broken prerequisite ordering
- expensive full regeneration

M34 introduces a persistent book-level production context.

## What M34 does NOT do

It does not replace M27–M33. It coordinates them.

For each lesson, the existing pipeline remains:

M27 → M28 → M29 → M30 → M31 → M32 → M33.

M34 decides when and how those stages are executed across the entire book.
