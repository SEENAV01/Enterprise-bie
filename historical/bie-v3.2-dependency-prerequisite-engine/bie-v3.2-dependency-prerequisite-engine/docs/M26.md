# M26 — Dependency + Prerequisite Engine

M26 adds a dedicated learning-dependency layer.

## Why this is different from the knowledge graph

The knowledge graph describes many kinds of relationships.
The dependency engine answers a narrower question:

**What must be understood before something else can be taught reliably?**

## Dependency types

- PREREQUISITE
- DEFINITIONAL
- CAUSAL
- PROCEDURAL
- MATHEMATICAL
- CONDITIONAL
- CONTEXTUAL
- APPLICATION
- ADVANCED_EXTENSION

## Three scopes

### BOOK_STATED
The source explicitly establishes the relationship.

### MODEL_INFERRED
The relationship is inferred from grounded reasoning and must be validated.

### EXTERNAL_HIGHER_KNOWLEDGE
The relationship leads beyond the book into higher knowledge and must be verified separately.

These scopes must remain distinct.

## Learning paths

The engine can traverse dependencies to construct a learning path.

Example:

Charge → Current → Ohm's Law → Circuit Analysis

The direction is explicitly represented so the lesson planner can order material.

## Gap detection

If a target requires prerequisites that are not in the learner's known set, the engine reports missing prerequisites rather than assuming readiness.

## Cycle detection

Learning dependencies should form an acyclic teaching order. Cycles are flagged for review because they may indicate a bad extraction or a genuinely circular relationship that needs special treatment.

## Critical rule

A model-inferred prerequisite is not automatically a fact. It carries confidence and requires validation.
