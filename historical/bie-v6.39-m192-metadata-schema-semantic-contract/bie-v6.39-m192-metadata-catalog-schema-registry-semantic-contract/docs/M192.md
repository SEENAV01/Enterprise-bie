# M192 — Metadata Catalog, Schema Registry & Semantic Contract Layer

M192 defines vendor-neutral contracts for metadata, schemas and semantic interoperability.

## Metadata

Metadata describes governed resources and carries ownership and tags.

## Schema registry

Schemas are versioned explicitly and associated with a resource. A schema contains fields and semantic-type assignments.

## Compatibility

Supported compatibility modes:

```text
NONE
BACKWARD
FORWARD
FULL
```

The reference implementation provides deterministic field-set compatibility checks.

## Semantic types

Semantic types give domain meaning to physical data types, for example a `CustomerId` represented by a string.

## Field contracts

Fields can declare:
- physical data type
- requiredness
- semantic type
- description

## Catalog

Catalog entries connect resources with schema, metadata and lineage references.

## Semantic contracts

A semantic contract captures producer, consumers, schema version and domain invariants.

## Schema governance

Governance can require approval before schema publication and can mandate a compatibility mode.

## Audit and observability

Schema lifecycle events and metrics are emitted for publishing and governance operations.

## Relationship

```text
M174 → Configuration

M191 → Data Lineage / Governance
```

## Important boundary

M192 does not implement a specific schema registry, catalog product, serialization format, or enterprise ontology. It defines portable contracts and extension points.
