# M33 — Render Orchestrator + QA Engine

M33 turns the compiled scene system into a controlled rendering pipeline.

## Responsibilities

1. Resolve render timing from finalized audio.
2. Build a content-addressed manifest for scenes.
3. Render only changed scenes when possible.
4. Run automated QA.
5. Classify failures.
6. Produce repair actions.
7. Allow rerender after repair.
8. Block final publishing when course QA fails.

## Incremental rendering

Each scene receives a fingerprint derived from:
- Scene DSL
- audio alignment
- asset manifest

If the fingerprint has not changed, the scene can be skipped during an incremental build.

This is essential for long books/courses where changing one scene should not force a complete rerender.

## QA

Current baseline checks include:
- scene identity
- audio-driven timing
- narration linkage
- missing visual layers
- render failure
- missing audio
- text overflow

Production QA can additionally inspect rendered frames for:
- clipping
- unreadable text
- overlap
- off-canvas objects
- accidental blank frames
- synchronization drift
- subtitle mismatch
- asset loading failures
- frame-rate/render consistency

## Repair loop

FAIL
→ classify
→ repair action
→ recompile
→ rerender changed scene
→ QA again

## Publishing gate

A course is publishable only after course-level QA passes.

## Important timing rule

Audio remains authoritative. Frame conversion happens only after actual audio timing is available.
