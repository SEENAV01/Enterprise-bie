# M195 — Distributed Coordination & Consensus Abstraction Layer

M195 defines vendor-neutral coordination contracts for distributed participants.

## Participants

A participant identifies a coordination member and can expose an endpoint and metadata.

## Epochs and leader terms

An epoch identifies a coordination configuration. A leader term binds a leader to an epoch and term number.

The abstraction does not prescribe Raft, Paxos, Viewstamped Replication or another specific consensus algorithm.

## Leases

Leases provide an explicit holder, expiry and renewability boundary. The implementation remains responsible for clock semantics and safe renewal.

## Quorum

A quorum declares members and the minimum acknowledgement count required for progress.

The reference implementation defaults to a majority quorum.

## Coordination lifecycle

The portable state sequence is:

```text
PREPARE → ACCEPT → FINALIZE
```

A final decision can be `COMMITTED` or `REJECTED`.

## Membership

Membership records identify the participant set and can describe stable, add, remove or replace transitions.

## Audit and observability

Coordination events record lifecycle operations and status. Metrics include term, latency and quorum state.

## Important boundary

M195 is an abstraction layer, not a consensus implementation. It does not provide leader election, replicated logs, failure detectors, Byzantine fault tolerance, network transport, or persistent membership storage.
