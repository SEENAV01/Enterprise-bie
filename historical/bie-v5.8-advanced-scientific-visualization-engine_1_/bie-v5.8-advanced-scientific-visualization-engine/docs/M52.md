# M52 — Advanced Mathematical & Scientific Visualization Engine

M52 provides structured representations for mathematics and science so visual generation is driven by meaning, not decoration.

## Supported structures

### Equations
Equations store LaTeX, variables and semantic meaning.

### Derivations
A derivation is represented as an ordered set of steps with explicit operations and parent steps.

This allows the video system to animate:
- substitution
- rearrangement
- simplification
- differentiation/integration
- vector operations
- limiting cases

without treating the equation as plain text.

### Coordinate systems and geometry

Coordinate systems, geometric objects and transformations can be represented independently from rendering.

### Vectors

Vectors store components and their coordinate system.

Vector operations are explicit, allowing animations such as:
- addition
- subtraction
- projection
- decomposition
- rotation

### Graphs

Graphs are driven by functions or data.

A parameter sweep is represented as a semantic animation, rather than an arbitrary object movement.

### Fields

Fields include:
- scalar fields
- vector fields
- domains
- mathematical rules
- units
- sampling/visualization rules

This creates a foundation for electric fields, gravitational fields, fluid flow and similar topics.

## Semantic binding

Every important visual should be linked to:
- the concept it explains
- its mathematical/physical state
- relevant narration cues

Therefore a visual transition has meaning.

For example:

`parameter increases`
→ curve changes according to the function

rather than:

`curve randomly morphs`

## Scientific integrity

Decorative animation must never silently alter scientific meaning.

The engine therefore separates:
- mathematical state
- visual representation
- animation transition

This is critical for educational correctness.

## Timing

Scientific animations remain content-driven. A derivation may take as long as needed for the narrator to explain each transformation.
