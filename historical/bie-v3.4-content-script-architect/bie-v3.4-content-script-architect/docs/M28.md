# M28 — Content + Script Architect

M28 converts a pedagogical lesson plan into structured teaching content.

## Responsibilities

M28 decides how each planned lesson block is expressed as:
- explanation
- definition
- intuition
- mechanism
- derivation step
- worked example
- application
- comparison
- misconception
- question
- recap
- transfer

## Grounding

Each unit retains evidence IDs. The script policy requires grounded claims and preserves source terminology.

The current implementation is an architectural baseline. Production generation should use a capable language model with the retrieved evidence packet as context, followed by claim-level validation.

## Narration

Narration is represented as units rather than one giant paragraph. Each unit can later receive:
- emphasis
- pause hints
- audio sync anchors
- pronunciation controls

## Visual instructions

M28 provides high-level visual intent. It deliberately does not yet generate final Remotion code or exact animation.

## Timing contract

There is no arbitrary scene duration.

Timing authority is:
**final narration audio + content requirements**.

Animation follows audio synchronization anchors, and a scene can extend until the explanation is complete.

## Critical distinction

M27 answered:
**What should be taught and in what order?**

M28 answers:
**How should each teaching unit be explained and narrated?**

The next layer will answer:
**Exactly what should be on screen and how should it be staged?**
