# M164 — Policy Decision, Rules & Dynamic Configuration Layer

M164 provides a controlled runtime mechanism for changing policy and configuration without changing application code.

## Rule definitions

Rules declare:
- identity
- condition
- effect
- priority
- scope

Supported reference effects:

```text
ALLOW
DENY
SET
UNSET
```

## Policy evaluation

Matching rules are ordered by priority. The highest-priority matching rule supplies the reference decision.

If no rule matches, the evaluator uses an explicit default, `DENY` in the compiler example.

Production policy engines can use richer expressions; this package intentionally keeps the reference evaluator deterministic and small.

## Rule composition

Rules can be composed with explicit operators such as AND/OR.

The reference layer stores the composition contract; it does not implement a full expression language.

## Dynamic configuration

Configuration has an explicit version, values, scope and lifecycle status:

```text
DRAFT → ACTIVE → INACTIVE
```

## Feature flags

Feature flags allow controlled activation of behavior.

A rollout percentage and optional scope can be associated with a flag.

## Safe rollout

Configuration changes can use:

```text
ALL_AT_ONCE
CANARY
PROGRESSIVE
```

A canary/progressive deployment should advance only after validation signals pass.

## Validation

Configuration versions can carry named checks. Activation should depend on validation success.

## Rollback

Rollback points to a known target version and records reason and requester.

This connects directly to M156 recovery and M151 reliability.

## Change audit

Every configuration transition can record:
- change ID
- configuration
- old version
- new version
- actor
- reason

This complements M155 audit/compliance evidence.

## Relationship

```text
M163 Security Enforcement
          ↓
M164 Policy / Configuration
          ↓
Decision / Runtime Config
          ↓
M162 APIs / M161 Workflows
```

## Important boundary

The reference implementation does not implement a production policy language, distributed configuration store, feature-flag service, traffic router, automatic canary analysis or secret management.
