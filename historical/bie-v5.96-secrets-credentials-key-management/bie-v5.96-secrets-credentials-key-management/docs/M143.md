# M143 — Secrets, Credentials & Key Management Layer

M143 defines how BIE workers obtain controlled access to external services without placing long-lived raw secrets into tasks or workflow state.

## Secret references

A secret is represented by a reference:

```text
secret_id
version
service
scope
```

The reference does not contain the raw secret value.

## Credential scopes

A credential scope can limit:
- service
- actions
- resources
- audience

This supports least-privilege access.

## Short-lived grants

A task can receive an access grant containing:
- grant ID
- secret reference
- scope
- subject
- issue time
- expiry time
- status

Grants can be revoked.

## Rotation

Rotation policies record:
- interval
- overlap period

The reference model can determine when rotation is due.

## Worker injection boundary

Workers receive a credential through an explicit injection request.

The contract intentionally states:

```text
payload_contains_raw_secret = false
```

The production secret broker is responsible for materializing the credential only inside the permitted execution boundary.

## Audit

Credential events can be recorded without storing raw secret values.

Audit records should capture:
- subject
- action
- service
- timestamp
- result
- secret reference

## Credential leases

Short-lived leases provide another explicit validity boundary for worker credentials.

## Relationship

M141 defines the worker runtime.

M143 controls what credentials that runtime may obtain.

```text
Task
 ↓
Credential Request
 ↓
Policy / Scope
 ↓
Short-lived Grant
 ↓
Worker Injection Boundary
 ↓
External Service
```

M134 can observe access events without exposing secrets.

M137 provenance can reference credential classes/versions without recording secret values.

## Important boundary

The reference implementation does not store or retrieve real secrets. Production deployments should use a dedicated secrets manager/KMS, hardware-backed or protected keys where appropriate, strong authentication, TLS, rotation, revocation and policy enforcement.

The sample signing/reference helpers are metadata contracts, not replacements for cryptographic key-management infrastructure.
