# M116 — Observability, Provenance & Audit Event Layer

M116 records what happened across the system as explicit, queryable events.

## Event model

An event can contain:
- event ID
- event type
- timestamp
- actor
- entity/resource reference
- correlation ID
- previous state
- new state
- evidence references
- build ID
- policy version
- metadata

## Append-only history

The reference model treats the audit log as append-only.

Existing history should not be rewritten as part of ordinary event recording.

This provides a foundation for trustworthy historical reconstruction.

## Correlation

A correlation ID connects events belonging to the same workflow.

Example:

```text
course-build-1842
    ↓
PLAN
    ↓
GENERATE
    ↓
EXECUTE
    ↓
VALIDATE
    ↓
RELEASE
```

Each event can carry the same root correlation identity with stage-specific context.

## Provenance

Entity lineage can be reconstructed from event references.

Example:

```text
source-text@2
      ↓
diagram@7
      ↓
scene@14
      ↓
video@3
      ↓
release@1842
```

## State transitions

Events can carry previous and new state.

This allows investigations such as:

```text
Why did artifact X become FAILED?
```

The answer can be reconstructed from the transition events and evidence references.

## Observability

Operational observations can be recorded separately from audit semantics.

Examples:
- execution duration
- status
- error
- resource metadata
- performance metrics

This allows production monitoring without mixing every operational metric into the core provenance model.

## Scope

The layer can record events from:
- planning
- generation
- execution
- asset updates
- validation
- release
- learner adaptation
- policy changes

The event vocabulary should remain extensible.

## Important boundary

An audit event says what the system recorded as having happened.

It does not by itself prove that the underlying event was truthful or that an actor was authorized.

Integrity, authorization and tamper-evidence can be strengthened by future security layers.

## Relationship

M113 tracks asset lineage.

M114 identifies reproducible builds.

M115 verifies artifacts.

M116 provides the chronological/event-level history connecting these operations.
