# M218 — Observability, Distributed Tracing, Metrics, Audit Log & Production Diagnostics

M218 makes the distributed engine diagnosable:

```text
Lesson Job
   ↓
Trace Context
   ├── Stage Spans
   ├── Worker Spans
   └── Render/QA Spans
        ↓
Structured Logs + Metrics
        ↓
Audit Log
        ↓
Diagnostics / Health
```

## Distributed tracing
A trace ID connects the full lesson lifecycle; spans represent individual stages and nested operations.

## Structured logging
Logs carry trace, span, job and node identifiers so failures can be correlated.

## Metrics
Counters, gauges and duration observations support operational dashboards and SLO calculations.

## Audit log
Security- and workflow-relevant actions are recorded with actor, action, target and result.

## Diagnostics
Logs, failed spans and metrics are combined into a machine-readable health assessment.

## Retention
Separate retention periods can be assigned to logs, traces and audit records.

## Boundary
M218 defines observability contracts and data models. Production deployment can export these signals to OpenTelemetry-compatible collectors, metrics systems and log stores.
