# M35 — Knowledge Expansion + Higher-Knowledge Engine

M35 implements the distinction that is central to the project's book-understanding goal:

**What the book says is not the same thing as what follows from the book, and neither is automatically the same as external higher knowledge.**

## Knowledge classes

The engine separates:
- BOOK_EXPLICIT — directly stated in the source
- BOOK_IMPLIED — strongly implied by the source
- PREREQUISITE — knowledge needed to understand the source
- APPLICATION — use of the source knowledge
- HIGHER_KNOWLEDGE — later/deeper knowledge that builds on it
- GENERALIZATION — broader abstraction
- EXTERNAL_CONTEXT — outside context

## Provenance

Every item can retain:
- book references
- external references
- model inference

These are represented separately.

## Verification gate

Higher knowledge, applications, generalizations and external context are not silently accepted.

They create verification requests. A retrieval/verification layer must provide evidence before such material is marked VERIFIED and allowed into teaching content.

## Dependency expansion

New knowledge can be connected to the existing knowledge graph. This allows the system to answer questions such as:

> What knowledge can be learned after this book concept?

and:

> What knowledge must already be known before this book concept?

## Critical safety against hallucinated curriculum

The system must not do:

Book concept → LLM imagination → teach as fact.

Instead:

Book concept
→ candidate expansion
→ external retrieval
→ evidence
→ verification
→ provenance
→ teaching gate
→ curriculum

## Production retrieval layer

M35 intentionally separates the reasoning/recording layer from the actual web/database retrieval provider. A production implementation can connect search, academic databases, textbooks, standards or other approved sources without changing the downstream knowledge schema.
