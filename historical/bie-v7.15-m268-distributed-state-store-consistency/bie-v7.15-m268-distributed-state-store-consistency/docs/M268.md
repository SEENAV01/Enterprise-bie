# M268 — Distributed State Store & Consistency Layer

```text
Workers / Control Plane
        ↓
   Shared State Store
        ↓
 Versioned State
        ↓
Optimistic Concurrency
        ↓
 Checkpoints + Event Log
        ↓
Consistency Check / Merge
        ↓
 Recovery + Replay
```

## Shared state
A common state store gives distributed workers and the control plane a normalized state contract.

## Versioning
Every successful write increments a version. Expected-version writes prevent stale workers from overwriting newer state.

## Checkpoints
Committed checkpoints provide recovery anchors for long-running runs.

## Consistency
Version gaps are detected, and newer remote state can be merged without blindly overwriting newer local state.

## Recovery
A run can restore from its latest committed checkpoint and replay events after a selected sequence.

## Boundary
M268 defines the consistency contract. Production deployments may replace the in-memory store with a transactional database, distributed KV store or event-sourced backend.
