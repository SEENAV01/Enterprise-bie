# M257 — Production Render Reliability

```text
M256 Worker
     ↓
Job Queue
     ↓
Resource Scheduler
     ├── CPU / RAM limits
     ├── concurrency
     └── priority
     ↓
Parallel Render Workers
     ↓
Checkpoint / Resume
     ↓
Retry + Failure Recovery
     ↓
Render Cache
     ↓
Verified MP4
```

## Queue
Jobs carry priority, attempt count, status and checkpoint state.

## Scheduling
Workers are selected only when requested CPU/RAM fit available capacity and concurrency limits.

## Checkpoint/resume
Frame checkpoints allow a failed or paused render to resume from a known frame rather than restarting conceptually from frame zero.

## Retry
Transient worker, timeout and I/O failures are retryable up to an explicit attempt limit.

## Cancellation
Queued/running/paused jobs can transition to CANCELLED and retain a reason.

## Cache
A deterministic SHA-256 key is derived from composition identity and relevant inputs. A matching artifact can bypass unnecessary re-render work.

## Important boundary
M257 specifies reliability behavior and contracts. It does not launch multiple OS/container workers itself; production deployment connects the scheduler to the actual worker pool.
