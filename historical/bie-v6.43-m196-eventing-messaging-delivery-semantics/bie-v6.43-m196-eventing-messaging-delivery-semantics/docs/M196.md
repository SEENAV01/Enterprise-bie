# M196 — Eventing, Messaging & Delivery Semantics Layer

M196 defines vendor-neutral event and message delivery contracts.

## Event envelopes

An event envelope carries an event ID, type, payload and optional source, timestamp and headers.

The event ID is the primary identity used by downstream deduplication and tracing.

## Topics and subscriptions

Topics provide named event streams with partition and retention hints. Subscriptions connect consumers to topics and may include a consumer group and filter expression.

## Ordering

Supported ordering semantics:

```text
NONE
PARTITION
GLOBAL
KEY
```

The contract does not dictate how a broker implements ordering.

## Delivery guarantees

Supported declarations:

```text
AT_MOST_ONCE
AT_LEAST_ONCE
EXACTLY_ONCE
```

Exactly-once is a semantic contract; an implementation must provide the required transactional/deduplication guarantees before claiming it.

## Retry and dead-letter

Retry policies define maximum attempts and backoff parameters. Dead-letter records preserve the original event reference and failure reason.

## Deduplication

Deduplication declares an identity key and optional time window for suppressing repeated delivery.

## Consumer groups and acknowledgements

Consumers identify a group, concurrency and acknowledgement mode. Acknowledgements can be `ACKED`, `NACKED` or `REQUEUED`.

## Audit and observability

Messaging lifecycle events and metrics capture publication/delivery operations, latency and delivery attempts.

## Important boundary

M196 does not implement Kafka, NATS, RabbitMQ, Pulsar, an event broker, network transport or a specific delivery algorithm. It establishes interoperable message semantics and integration contracts.
