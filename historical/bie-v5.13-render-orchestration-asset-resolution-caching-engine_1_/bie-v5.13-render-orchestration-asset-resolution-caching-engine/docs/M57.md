# M57 — Render Orchestration, Asset Resolution & Caching Engine

M57 turns the renderer-ready scene graph into an efficient production workflow for large courses.

## Why it exists

A long course can contain hundreds or thousands of scenes. Re-rendering everything after every change is wasteful.

M57 introduces:
- dependency graphs
- asset resolution
- content-addressed cache keys
- incremental rendering
- independent scene jobs
- retry classification
- parallel scheduling
- final assembly manifests

## Dependency graph

Scenes explicitly declare their asset dependencies.

This allows the system to determine what must be invalidated when an asset or scene changes.

## Asset resolution

Every referenced asset must resolve against the asset library.

Missing assets are a blocking quality-gate error.

## Deterministic caching

A cache key is derived from:
- scene IR
- renderer version
- asset manifest

Therefore a scene can be reused when its effective inputs have not changed.

## Incremental rendering

If 1 scene changes in a 500-scene course, the scheduler should render only the affected jobs rather than blindly rendering all 500.

Future dependency invalidation can expand the affected set when shared assets change.

## Parallelism

Independent ready jobs are represented as parallelizable render jobs.

A production worker pool can consume these jobs.

## Retry strategy

Transient failures such as worker failure, timeout or temporary I/O can be retried.

Validation failures such as missing assets or invalid timelines should not be blindly retried; they need correction upstream.

## Final assembly

Rendered scene outputs are ordered through an assembly manifest.

The manifest records:
- scene order
- dimensions
- FPS
- final assembly readiness

## Relationship to previous modules

M56 answers:

`How does a planned scene become renderer-ready?`

M57 answers:

`Which scenes need rendering, what dependencies do they have, can existing results be reused, how should jobs be scheduled, and how are outputs assembled?`

## Important distinction

M57 is infrastructure, not pedagogy.

It does not decide what the learner should see. It makes the already-decided content production-efficient.
