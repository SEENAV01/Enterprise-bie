# M99 — Evaluation, Benchmarking & Policy Optimization Layer

M99 converts M98 evidence into controlled optimization decisions.

## Evaluation suites

An evaluation suite defines:
- targets
- metrics
- scenarios
- version

Evaluation cases can define:
- target
- inputs
- expected behavior
- constraints

This makes comparisons repeatable.

## Benchmarking

Benchmarks compare a target against:
- a baseline
- another implementation
- another representation
- another renderer
- another correction strategy

The benchmark is versioned and traceable to its evaluation suite.

## Multi-objective scoring

A production/learning system cannot optimize one number blindly.

M99 supports objectives such as:
- quality
- learning outcome
- cost
- latency
- reliability
- accessibility

Objectives have direction and weight.

A normalized weighted score can provide a common comparison signal.

The score is a decision aid, not an absolute truth.

## Evidence-linked recommendations

Recommendations explicitly contain:
- confidence
- evidence references
- expected effects
- risks
- target policy
- proposed action

This prevents an optimization rule from appearing without an evidence trail.

## Bounded optimization

M99 deliberately does not create uncontrolled self-modification.

Policy changes have:
- version
- scope
- rationale
- evidence
- approval state

The reference guardrail can reject changes outside an allowed scope or without evidence.

## Human approval

A policy change may remain `PENDING_APPROVAL`.

Only approved changes pass the policy-change quality gate.

Future deployments can introduce automated approval for narrowly bounded, pre-authorized policy classes without changing this architecture.

## Example

Suppose experiments show:

`interactive > static` on mastery

but:

`interactive > static` also increases cost substantially.

M99 can recommend a conditional policy:

`Use interactive representation for concept class X when expected mastery gain exceeds threshold and cost budget permits.`

The recommendation is evidence-linked and can be reviewed before activation.

## Relationship

M98 measures system behavior.

M99 evaluates alternatives and proposes controlled optimization.

The resulting policy can feed future planning/routing systems, but remains versioned and bounded.
