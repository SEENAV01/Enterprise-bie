# M212 — Automated Remediation & Regeneration Loop

M212 closes the render/QA feedback loop:

```text
QA Failure
   ↓
Failure Classification
   ↓
Root-Cause Diagnosis
   ↓
Impact Analysis
   ↓
Targeted Remediation
   ↓
Partial Regeneration
   ↓
Re-render / Re-QA
   ↓
PASS → Verified Artifact
FAIL → bounded next cycle / escalation
```

## Failure classification

Failures are categorized by affected production layer such as visual, audio, sync, caption, render, content or layout.

## Diagnosis

Each failure maps to a root cause and affected references with confidence and rationale.

## Minimal-scope remediation

The system can regenerate only the affected asset/scene while explicitly preserving unaffected references.

## Impact analysis

The loop identifies failed references, preserved references, rerender scope and dependencies.

## Regeneration

A regeneration job records the remediation action, targets, inputs and attempt number.

## Re-QA

The regenerated result re-enters QA. A cycle is PASS, FAIL or REVIEW.

## Guard

A bounded attempt policy prevents uncontrolled regeneration loops and supports escalation.

## Provenance

Every remediation loop remains linked to the original render job, failure, diagnosis, remediation and QA report.

## Boundary

M212 defines the control/decision contract. Actual diagnosis models, asset generation, rendering and media inspection are delegated to downstream implementations.
