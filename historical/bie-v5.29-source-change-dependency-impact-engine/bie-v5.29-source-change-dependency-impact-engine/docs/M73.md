# M73 — Source Change & Dependency Impact Analysis Engine

M73 determines what must change when an upstream source or canonical knowledge record changes.

## Core problem

Large courses cannot be rebuilt from scratch after every source edit.

M73 traces:

`Source → Concept → Lesson → Scene → Visual/Audio/Assessment → Render`

and identifies downstream artifacts that may now be stale.

## Impact analysis

A dependency graph is traversed from changed nodes.

Every downstream node becomes an impact candidate.

## Minimal regeneration

Only affected, non-protected artifacts enter the regeneration plan.

Unchanged unrelated artifacts remain untouched.

## Change safety

Not every detected source change should automatically propagate.

The reference policy includes:
- normal updates → proceed
- low-confidence changes → review
- high-risk/deletion/untrusted replacement → block

## Semantic change

A textual diff is not necessarily a pedagogical change.

The architecture therefore exposes a semantic-change signal.

If meaning changes, downstream knowledge and pedagogical artifacts should be reassessed rather than blindly patched.

## Protection

Validated canonical records can be protected from accidental mutation.

Historical versions remain separate.

## Relationship to M71/M72

M71 handles course-level production.

M72 stores versioned reusable knowledge and artifacts.

M73 determines the consequences of changes to those upstream records.

Together they enable:
- incremental regeneration
- stale-artifact detection
- controlled propagation
- reproducible course maintenance

## Domain independence

M73 is not tied to Physics or textbooks. Any dependency graph of structured educational content can use it.
