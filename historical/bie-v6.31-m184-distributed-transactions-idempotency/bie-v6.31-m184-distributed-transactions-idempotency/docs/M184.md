# M184 — Distributed Transactions, Idempotency & Exactly-Once Effect Layer

M184 defines reliable state/effect coordination without requiring a global distributed ACID transaction.

## Transactions

A transaction groups operations under an explicit boundary.

Reference outcomes:

```text
ACTIVE
COMMITTED
ABORTED
```

## Idempotency

An idempotency key is paired with a request hash.

```text
Request
  ↓
Idempotency Key
  ↓
Already applied?
  ├── YES → reuse prior result
  └── NO  → execute
```

A conflicting request using the same key but a different request hash must not silently reuse the old result.

## Inbox

Inbound events are recorded before processing and can transition to CONSUMED.

This gives consumers a durable deduplication boundary.

## Outbox

State change and outbox creation are intended to occur in the same local transaction.

The publisher later transitions the outbox event to PUBLISHED.

## Exactly-once effect

The contract targets exactly-once business effects even when delivery is at-least-once.

This is achieved through idempotency and durable effect records rather than assuming exactly-once network delivery.

## Saga / compensation

Distributed workflows can define compensation for already-completed steps.

Compensation is explicit; not every external operation is assumed reversible.

## Recovery

Retries are bounded by a recovery policy.

Backoff is represented as configuration rather than tied to a specific queue/runtime.

## Observability

Transaction events record:
- transaction ID
- operation
- status
- latency
- duplicate indication

These feed M150.

## Important boundary

M184 does not implement a global XA/2PC transaction manager. It provides contracts for local atomicity, idempotent effects, reliable event publication and compensation.
