# M216 — Distributed Worker Execution, Queueing, Resource Allocation & Fault-Tolerant Batch Runtime

M216 turns M215's batch plan into a fault-tolerant execution layer:

```text
Batch Plan
   ↓
Job Queue
   ↓
Worker Selection
   ↓
Resource Allocation
   ↓
Execution Attempt
   ├── Success → Result Aggregation
   └── Failure → Checkpoint → Retry / Requeue
                          ↓
                    Worker Recovery
                          ↓
                    Result Aggregation
```

## Queue

Jobs are uniquely enqueued and dequeued.

## Workers

Workers advertise capabilities and have explicit lifecycle status.

## Resource allocation

CPU, memory and GPU capacity are represented as allocatable resources. A job cannot consume resources that are unavailable.

## Attempts and retries

Every execution attempt is tracked independently. Retry policy bounds the number of attempts and distinguishes retryable failures.

## Checkpointing

A job can persist a checkpoint containing stage, artifact references and execution state so recovery can resume from a known boundary.

## Worker failure recovery

Worker loss identifies affected jobs and can requeue them when recovery is possible.

## Result aggregation

The runtime aggregates individual job results into a batch-level status.

## Boundary

M216 defines the runtime control contracts; actual distributed infrastructure (Kubernetes, Celery, Ray, Temporal, cloud queues, etc.) remains an implementation choice.
