# M145 — API Gateway & Service Contract Layer

M145 defines stable synchronous interfaces for external clients and internal services.

## Routing

Routes bind:
- HTTP method
- normalized path
- target service
- optional authorization scope
- API version

## Service contracts

A contract describes:
- service name
- version
- request schema
- response schema
- allowed error codes

This creates an explicit interface boundary.

## Authentication and authorization

An authentication context identifies a subject and credential.

Authorization is expressed through scopes.

```text
Request
 ↓
Authentication
 ↓
Authorization Scope
 ↓
Route
 ↓
Service
```

## Rate limiting

Rate-limit policies define a request count and time window.

The reference implementation provides a simple count check. Production implementations should use distributed counters/token buckets as required.

## Idempotency

Mutating requests can provide an idempotency key.

A stored request hash prevents the same key from being reused for a different request.

Completed responses can be reused.

## Error contract

Standard error codes include:
- VALIDATION_ERROR
- UNAUTHORIZED
- FORBIDDEN
- NOT_FOUND
- CONFLICT
- RATE_LIMITED
- INTERNAL_ERROR

Errors carry request and correlation identifiers where available.

## Versioning

API versions are explicit.

Compatibility checks provide a basic contract comparison. Production schema compatibility should use a formal schema-diff policy.

## Pagination

List responses use bounded page sizes and cursors.

## Correlation

Requests can carry correlation IDs that connect synchronous API traffic to M144 asynchronous events and M140 workflow execution.

## Relationship

```text
Client
 ↓
API Gateway (M145)
 ↓
Service Contract
 ↓
BIE Service
 ↓
M144 Event Bus
 ↓
M140 Workflow
 ↓
M141 Worker
```

M143 supplies credential boundaries for service-to-service access.

M134 can observe API latency/error metrics.

## Important boundary

The reference layer does not implement a production HTTP server, TLS termination, distributed rate limiter, JWT/OIDC validation, WAF, schema validator or service mesh.

Those are deployment concerns that can implement these contracts.
