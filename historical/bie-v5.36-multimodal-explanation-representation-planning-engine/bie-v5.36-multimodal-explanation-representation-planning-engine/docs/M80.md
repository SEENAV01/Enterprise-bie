# M80 — Multimodal Explanation & Representation Planning Engine

M80 decides how a teaching unit should be represented.

## Representation choices

Reference modalities include:
- narration
- text
- diagram
- illustration
- animation
- equation
- simulation
- table
- comparison
- analogy
- interaction

The architecture does not assume animation is always superior.

## Purpose-driven selection

Each representation can carry an explanation purpose and priority.

Production planners can score representations against signals such as:
- process/change over time
- spatial relationship
- symbolic reasoning
- comparison
- causal explanation
- learner manipulation

## Multimodal composition

A unit can combine several representations.

The engine provides an overlap guard to flag potentially redundant combinations, such as narration + large blocks of identical text.

This is a planning signal, not an automatic prohibition.

## Cognitive load

A budget model separates:
- intrinsic load
- extraneous load
- germane load

Plans exceeding the configured budget are flagged for review.

This gives the production system a measurable reason to simplify a scene.

## Synchronization

Representation plans can contain synchronization hooks.

Examples:
- equation term appears when narrated
- diagram node highlights when referenced
- animation starts at a verbal cue
- simulation control becomes available after explanation

Exact timing remains downstream in temporal planning.

## Scene intent

Scene intent records connect:
`objective → explanation goal → representations`

This makes the later scene compiler aware of why a visual exists.

## Provenance

Representations should retain concept, objective and source references.

## Domain independence

M80 is domain-agnostic.
