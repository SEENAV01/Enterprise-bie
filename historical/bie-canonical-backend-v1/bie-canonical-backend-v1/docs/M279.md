# M279 — Source Intake & Document IR

M279 is the first real input boundary in the canonical BIE pipeline.

```text
PDF / EPUB / TXT / MD
        ↓
Source Intake
        ↓
Format-specific Extraction
        ↓
Stable Block IDs + Locators
        ↓
Document IR v1.0
        ↓
Understanding / Knowledge / Planning
```

## Implemented

- PDF extraction through `pypdf`
- page-aware PDF blocks
- explicit scanned-PDF `NEEDS_OCR` state
- EPUB XHTML/HTML extraction
- text/Markdown ingestion
- stable content-derived block IDs
- source URI and locator preservation
- Document IR v1.0
- integration into the canonical M278 pipeline
- source readiness QA gate
- adapter tests

## Important boundary

OCR is **not** falsely claimed as implemented. An image-only PDF becomes `NEEDS_OCR` and cannot pass the publish gate.

Likewise, extraction does not yet claim full layout reconstruction, tables, equations, figures, footnotes or semantic understanding. Those belong behind the next adapters.

## Why this is the right next step

The previous integration spine used a synthetic understanding artifact. M279 replaces that placeholder with an actual file-input boundary. The project can now start from a real source rather than a hard-coded demo source.
