# M19 — Production Visual Engine + Asset Resolver

M19 establishes the visual layer that sits between Scene DSL and Remotion.

## Visual primitives

The system supports a renderer vocabulary rather than arbitrary visual generation:
- text
- diagrams
- equations
- charts
- tables
- process animations
- simulations
- real-world visuals
- mixed compositions

## Asset resolver

Every referenced asset is resolved through a registry.
Missing assets are explicitly reported rather than silently replaced.

## Visual selection

The pedagogical scene type determines an initial visual strategy:
- definition → mixed
- causal/process → process
- derivation → equation
- diagram explanation → diagram
- comparison → table
- application → real-world
- checkpoint → text

This is only the initial plan. The planner may select a richer mixed composition when the explanation requires it.

## Audio synchronization

Visual actions are marker-driven.
Word/phoneme timestamps from actual TTS or recorded narration can trigger:
- equation term reveals
- diagram labels
- process steps
- highlights
- camera cues
- chart growth

## No fixed duration

The visual engine never assumes a fixed duration per scene. It receives the authoritative audio duration/timestamps and fills the explanatory timeline accordingly.

## Quality direction

The included Remotion primitives establish the interface, not the final visual quality. Production implementations should add SVG/canvas rendering, KaTeX/MathJax-compatible equation rendering, animated graphs, diagram tracing, asset compositing, camera choreography and deterministic transitions.

## Next

M20 should build the actual asset-generation/retrieval and high-fidelity visual renderers, including diagram reconstruction, math rendering, chart/table animation, captions and media composition, then connect them to final MP4 rendering.
