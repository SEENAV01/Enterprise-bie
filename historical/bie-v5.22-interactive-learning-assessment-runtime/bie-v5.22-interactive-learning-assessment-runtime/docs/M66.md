# M66 — Interactive Learning & Assessment Runtime

M66 turns the pedagogical plan into an interactive learner loop.

## Core loop

`Question → Response → Evaluation → Feedback → Mastery Update → Next Action`

## Questions

Questions explicitly reference concepts and can specify:
- response type
- expected answer
- rubric
- difficulty
- hints

## Response evaluation

Objective questions can be automatically evaluated.

Questions without a machine-checkable answer are routed to rubric/manual review rather than being falsely marked correct or incorrect.

## Feedback

Feedback is downstream of evaluation.

Possible actions include:
- continue
- retry
- show hint and retry

## Hints

Hints are attempt-aware so repeated attempts can progressively reveal assistance.

## Mastery

Mastery is updated after machine-evaluable attempts using a bounded update rule.

The reference implementation is intentionally simple; a production model can replace it with Bayesian, IRT, BKT or other validated approaches.

## Misconception signals

Repeated incorrect response patterns can be surfaced as signals.

M66 does not automatically declare a learner to have a misconception from one mistake.

Signals can feed M65 for targeted intervention.

## Persistence

Learner state includes:
- mastery
- attempt history
- misconception signals

This allows adaptation across lessons instead of treating every lesson as isolated.

## Important boundary

M66 evaluates learner responses; it does not rewrite the underlying knowledge model.

## Relationship to M65

M65 chooses how to teach.

M66 observes what the learner does and updates learner state.

The loop is:

`M65 strategy → M66 interaction → learner state → M65 adaptation`
