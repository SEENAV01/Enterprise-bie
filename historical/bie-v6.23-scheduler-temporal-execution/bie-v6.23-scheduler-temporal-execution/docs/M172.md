# M172 — Scheduler, Timers & Temporal Execution Layer

M172 provides broker- and scheduler-neutral temporal execution contracts.

## Schedules

A schedule binds a target reference to a start time and timezone.

Schedules can be enabled or disabled.

## Recurrence

Reference frequencies:

```text
ONCE
MINUTELY
HOURLY
DAILY
WEEKLY
MONTHLY
```

Recurrence can be bounded by count or end time.

## Timers

A timer represents a single future execution point:

```text
SCHEDULED
   ↓
DUE
   ↓
EXECUTE
```

## Delayed jobs

Delayed jobs are explicit scheduled work items with an attempt counter.

## Misfire handling

A misfire occurs when an execution opportunity is missed.

Reference policies:

```text
SKIP
RUN_NOW
CATCH_UP
COALESCE
```

## Execution leases

Leases prevent multiple workers from simultaneously claiming the same execution.

```text
HELD
 ↓
VALID
 ↓
EXPIRED / RELEASED
```

The reference layer models the lease contract; distributed coordination belongs to the runtime adapter.

## Execution windows

A job can be constrained to a valid execution window.

This is useful for:
- maintenance windows
- business hours
- resource availability
- policy-controlled execution

## Cancellation

Temporal targets can transition:

```text
REQUESTED
   ↓
CANCELLED
```

Cancellation must propagate to the underlying workflow/job runtime.

## Retry coordination

Temporal retry policies support fixed, linear and exponential backoff.

Retry coordination remains distinct from M171 message retries: M172 governs time-based execution attempts.

## Observability

Temporal events capture:
- target
- operation
- status
- scheduled time
- start time
- latency

This feeds M150 telemetry.

## Relationship

```text
M171 Messaging
      ↓
M172 Temporal Execution
      ↓
M161 Workflows
      ↓
M167 Persistence / M170 Objects
```

M171 can carry scheduled commands/events.

M164 policies can constrain execution windows and schedules.

M163 authorization controls who can create/change/cancel schedules.

M166 retention/privacy rules remain applicable to temporal metadata.

## Important boundary

The reference layer does not implement Quartz, Temporal Server, Airflow, cron infrastructure, distributed locks, clock synchronization or a production scheduler cluster.
