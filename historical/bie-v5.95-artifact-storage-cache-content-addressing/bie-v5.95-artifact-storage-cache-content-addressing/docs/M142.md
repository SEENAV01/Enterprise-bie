# M142 — Artifact Storage, Cache & Content-Addressable Data Layer

M142 provides the durable data backbone for artifacts produced and consumed by BIE workers.

## Content-addressable identity

Artifact content can receive a SHA-256 content ID.

```text
Content
  ↓
SHA-256
  ↓
sha256:<digest>
```

The same content therefore receives the same content identity.

## Immutable artifacts

An artifact record carries:
- artifact ID
- content ID
- size
- media type
- metadata
- immutable marker

The content ID is the integrity anchor.

## Storage locations

An artifact can have one or more storage locations and an explicit storage tier.

This supports future hot/warm/cold storage policies.

## Cache

Cache keys represent:

```text
Operation
+
Inputs
+
Configuration
```

A cache entry maps the key to an existing content ID.

This enables expensive transformations to be reused.

## Deduplication

A content-index can map one content ID to multiple artifact references.

Identical content can therefore avoid unnecessary duplicate storage.

## Transfer

Transfers record:
- source
- destination
- content ID
- size

A transfer is complete only after checksum verification in the reference contract.

## Retention

Retention policies can express:
- maximum age
- version count
- target tier

The reference model returns KEEP, EXPIRE or PRUNE_OLD_VERSIONS.

## Signed references

A reference signature can bind a content ID to a signing-key identifier.

Production deployments should use real asymmetric signatures and a secure key-management system; the reference implementation uses a deterministic placeholder construction.

## Integrity

Stored/retrieved bytes can be hashed again and compared with the expected content ID.

## Relationship

M141 workers consume and create artifacts.

M142 makes those artifacts persistently addressable and efficiently reusable.

M137 provenance references artifacts.

M139 media pipelines produce derived artifacts.

M140 orchestrates tasks that move artifacts through the system.

## Important boundary

The reference implementation models contracts and identity; it does not implement an object store, distributed cache, CDN, encryption-at-rest, multipart transfer protocol or production key management.
