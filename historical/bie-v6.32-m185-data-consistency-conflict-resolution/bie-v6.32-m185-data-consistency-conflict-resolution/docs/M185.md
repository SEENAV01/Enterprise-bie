# M185 — Data Consistency, Conflict Resolution & Replicated State Convergence Layer

M185 defines vendor-neutral contracts for replicated state convergence.

## Logical clocks

Logical clocks provide monotonic ordering within a node.

## Vector clocks

Vector clocks capture causal relationships across nodes.

They distinguish causally ordered versions from concurrent versions.

## Versioned state

State carries its causal clock and optional writer identity.

## Conflict detection

Concurrent writes can be represented explicitly as conflicts rather than silently overwritten.

## Merge policies

Reference policies:

```text
LAST_WRITE_WINS
FIRST_WRITE_WINS
CUSTOM
MULTI_VALUE
```

A custom resolver is an extension point, not an implementation of application-specific merge logic.

## Tombstones

Deletes are represented as tombstones so replicas can propagate deletion state during reconciliation.

## Anti-entropy

Replicas can exchange state and reconcile differences using resumable peer/cursor contracts.

## Reconciliation

Reference actions:

```text
MERGE
REPLACE_LEFT
REPLACE_RIGHT
DELETE
```

## Divergence

A divergence record captures peer identities and the number of detected differences.

## Consistency

Reference modes:

```text
EVENTUAL
CAUSAL
BOUNDED_STALENESS
STRONG
```

Read repair can be enabled as a policy.

## Observability

Consistency events capture:
- key
- operation
- status
- divergence count
- merge count

These feed M150.

## Relationship

```text
M173 → Coordination
M177 → Distributed State
M184 → Transaction / Effect Safety
M185 → Convergence / Conflict Resolution
M150 → Consistency Observability
```

## Important boundary

M185 does not implement a specific CRDT library, consensus algorithm, database replication engine, or conflict resolver for arbitrary business objects.
