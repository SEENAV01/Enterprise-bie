# M173 — Distributed Coordination & Locking Layer

M173 defines coordination contracts required when multiple workers may act on the same logical resource.

## Leases

A lease gives a worker temporary ownership:

```text
HELD
 ↓
VALID
 ↓
EXPIRED / RELEASED
```

Leases are time-bounded and include an ownership epoch.

## Fencing tokens

Fencing prevents an old owner from continuing to write after a newer owner has taken control.

```text
Owner A → epoch 6
Owner B → epoch 7

epoch 6 write → reject
epoch 7 write → allow
```

The token must be checked by the protected resource/adapter.

## Distributed mutex

Reference modes:

```text
EXCLUSIVE
SHARED
```

The contract models acquisition state without prescribing a specific locking service.

## Leader election

A coordination group can have a leader and leadership epoch.

Leadership is explicitly identifiable by group and worker.

## Quorum

A quorum contract defines the minimum acknowledgements required among nodes.

The default reference quorum is a majority.

```text
5 nodes
3 required
```

This is a contract, not an implementation of Raft/Paxos.

## Ownership epochs

Ownership epochs monotonically identify newer ownership.

A newer epoch supersedes an older epoch.

## Failure detection

Nodes can be considered suspected after their heartbeat exceeds the configured timeout.

Failure detection is intentionally modeled as suspicion rather than absolute proof of failure.

## Coordination requests

Operations include:

```text
ACQUIRE
RENEW
RELEASE
TRANSFER
```

## Observability

Coordination events capture:
- resource
- operation
- status
- owner
- epoch
- latency

This feeds M150 telemetry.

## Relationship

```text
M172 Temporal Execution
       ↓
M173 Coordination
   ↙        ↘
M161       M167
Workflow   Persistence
```

M171 messaging may carry coordination events.

M163 authorization governs who may acquire/transfer ownership.

M164 policy can constrain lease durations, quorum requirements and leadership.

## Important boundary

The reference layer does not implement Redis locks, ZooKeeper, etcd, Consul, Raft, Paxos, distributed consensus, clock synchronization or production failure detectors.
