# M115 — Validation, Quality Gates & Artifact Verification

M115 establishes the acceptance boundary between generated artifacts and released artifacts.

## Core principle

Successful execution is not proof of correctness.

```text
Generated
   ↓
Executed
   ↓
Artifact
   ↓
Verification
   ↓
Quality Gate
   ↓
Release / Repair
```

## Validation categories

The architecture supports separate checks for:
- semantic correctness
- structural integrity
- dependency completeness
- accessibility
- media constraints
- reproducibility

Additional domain-specific categories can be added without changing the core model.

## Evidence

Every check can carry evidence.

This is important because a release decision should be explainable rather than being a hidden model judgment.

Example:

```text
semantic: PASS
structure: PASS
dependencies: PASS
accessibility: WARN
timing: FAIL
```

## Quality gates

A gate defines:
- required validation categories
- statuses that cause failure

A missing required category can prevent release.

This avoids a system accidentally treating “not checked” as “passed.”

## Accessibility

Accessibility is treated as a validation category rather than an optional post-processing thought.

The reference validator demonstrates checks for:
- captions
- alt text
- transcript

The exact requirements can be policy-specific.

## Media validation

Media metadata can be checked against explicit constraints such as:
- maximum duration
- required frame rate
- dimensions

More constraints can be added for codecs, audio channels, loudness, subtitle timing and platform limits.

## Reproducibility verification

M114 declares a reproducibility manifest and digest.

M115 can compare declared and observed build identities as part of acceptance.

## Release decision

A verification report combines:
- individual check results
- summary counts
- gate outcomes
- release eligibility

Only passing gates make an artifact release-eligible.

## Repair loop

A failed artifact should not simply disappear.

```text
FAIL
 ↓
diagnose
 ↓
repair/rebuild
 ↓
re-verify
 ↓
PASS
```

Failures should remain attributable to the specific check and evidence that triggered them.
