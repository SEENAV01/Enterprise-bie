# M45 — Production Visual Component System

M45 defines the reusable visual component layer used by the renderer.

## Why this layer exists

Without a component system, every generated scene would produce custom rendering code.

That causes:
- inconsistent visual language
- duplicated logic
- difficult maintenance
- poor performance
- unpredictable animation behavior

M45 instead provides semantic components with stable contracts.

## Semantic components

Core components include:

### Equation
Used for mathematical reasoning and derivation.

Supports:
- structured expressions
- part-by-part reveal
- term highlighting
- accessibility alt text

### Diagram
Used for structural and causal relationships.

Supports:
- nodes
- semantic edges
- automatic layout
- descriptions

### Graph
Used for quantitative relationships.

Supports:
- axes
- series
- labels
- annotations

### Process
Used for procedures and sequences.

Supports:
- ordered steps
- current-step highlighting
- directional layout

### Particle System
Used when motion itself communicates a process.

Supports:
- deterministic seed
- path
- speed
- controlled particle count

### Camera
Used to guide attention and navigate complex visuals.

### KnowledgeText
Used for explanatory text rather than decorative text.

## Motion

Motion primitives are semantic:

APPEAR
FADE
WRITE
DRAW
TRACE
MOVE
MORPH
HIGHLIGHT
TRANSFORM

The animation API receives frame boundaries from M42/M44 rather than inventing timing.

## Audio cues

Audio cues are first-class events.

Example:

audio cue at frame 210
→ equation term highlight

This keeps visual emphasis synchronized with speech.

## Performance

Educational videos can contain thousands of visual objects. The component layer therefore establishes policies for:
- memoization
- precomputed geometry
- bounded particle counts
- avoiding DOM growth
- efficient static diagrams

## Accessibility

Components should expose:
- captions
- descriptions
- equation alt text
- safe text areas
- contrast checks

## API stability

A component contract separates pedagogical intent from implementation.

For example:

`EQUATION` means mathematical reasoning.

The actual implementation can later change from SVG to another renderer without changing the upstream knowledge/pedagogy pipeline.

## Critical boundary

M45 does not decide:
- what to teach
- what is important
- what the narration says
- how long the lesson is

It executes the specification created upstream.

## Next

M46 should build the Intelligent Scene Orchestrator: select and compose multiple components within each scene, manage spatial relationships and visual hierarchy, prevent occlusion/clutter, coordinate simultaneous animations, and optimize scenes for comprehension rather than merely rendering every requested object.
