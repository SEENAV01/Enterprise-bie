# M179 — Object/Blob Storage & Artifact Lifecycle Layer

M179 defines durable object and artifact contracts independently of a storage vendor.

## Object identities

Objects are addressed by:
- object ID
- bucket/namespace
- key
- optional version

## Namespaces

Namespaces can be scoped to a tenant and region.

## Metadata

Reference metadata includes:
- content type
- size
- custom attributes

## Multipart uploads

Large artifacts may be uploaded in parts.

```text
INITIATED
   ↓
PARTS
   ↓
COMPLETED
```

The reference contract verifies that the expected number of parts exists.

## Checksums

Supported reference algorithms:

```text
MD5
SHA256
SHA512
```

Checksums provide integrity verification.

## Content addressing

Content-addressed objects use a deterministic algorithm/hash address.

Identical addresses represent identical content in the reference contract.

## Versioning

Object versions identify immutable generations and can mark the current version.

## Retention

Reference policies:

```text
NONE
TIME_BASED
INDEFINITE
```

Retention can prevent deletion while protection applies.

## Legal holds

A legal hold independently protects an object from lifecycle deletion.

## Lifecycle transitions

Reference storage classes:

```text
STANDARD
INFREQUENT
ARCHIVE
DELETED
```

Lifecycle rules can transition objects based on conditions.

## Signed access

Signed access references represent time-bounded GET/PUT/DELETE permissions and constraints.

They do not themselves implement cryptographic signing.

## Artifacts

Artifacts can carry:
- artifact type
- source reference
- manifest

This is important for generated videos, models, datasets and other build outputs.

## Observability

Storage events capture:
- object
- operation
- status
- bytes
- latency

These feed M150.

## Relationship

```text
M167 Persistence
      ↓
M179 Object Storage
   ↙       ↘
M170      M150
Artifacts Telemetry
```

M174 supplies storage configuration.

M165 supplies signing/key material.

M171 can distribute lifecycle/invalidation events.

M172 can schedule lifecycle transitions and cleanup.

M177 may cache artifact metadata.

## Important boundary

The reference layer does not implement S3, GCS, Azure Blob Storage, filesystem drivers, erasure coding, object replication, CDN delivery or actual cryptographic signing.
