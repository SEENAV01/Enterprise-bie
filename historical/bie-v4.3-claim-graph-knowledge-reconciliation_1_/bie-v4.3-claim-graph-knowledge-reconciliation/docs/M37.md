# M37 — Claim Graph + Knowledge Reconciliation Engine

M37 creates the canonical knowledge graph that sits between evidence retrieval and curriculum generation.

## Why this layer is necessary

Multiple sources may:
- state the same claim using different wording
- use different terminology
- provide overlapping evidence
- disagree
- describe different levels of abstraction

The curriculum should not simply append every retrieved statement.

## Canonical claim process

Retrieved claims
→ normalization
→ duplicate clustering
→ canonical claim
→ evidence aggregation
→ uncertainty/conflict state
→ curriculum gate

## Graph structure

The graph can represent:
- concepts
- claims
- definitions
- processes
- causes
- applications
- examples
- prerequisites
- higher knowledge
- sources

Relationships include:
- defines
- supports
- contradicts
- depends on
- causes
- applies to
- example of
- extends
- generalizes
- sourced by

## Contradictions

Conflicting claims are preserved rather than silently overwritten.

A conflict can block automatic curriculum consumption until resolved.

## Terminology reconciliation

A canonical term can have aliases. This supports consistency across a book even when different sources use slightly different terminology.

## Uncertainty

Claims can be marked:
- HIGH_CONFIDENCE
- SUPPORTED
- CONFLICTED
- UNSUPPORTED

The graph therefore represents uncertainty explicitly rather than pretending every retrieved statement is equally certain.

## Important distinction

M37 reconciles knowledge structure. It does not decide pedagogy.

The pedagogical system later decides:
- what to teach
- when to teach it
- how deeply
- which examples to use
- which knowledge belongs in the main lesson versus enrichment
