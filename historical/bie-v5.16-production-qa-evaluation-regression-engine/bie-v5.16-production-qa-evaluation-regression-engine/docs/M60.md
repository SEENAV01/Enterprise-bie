# M60 — Production QA, Evaluation & Regression Engine

M60 is the verification layer before final delivery.

## Goal

Generated content should not be treated as correct merely because it rendered successfully.

M60 checks:
- structural validity
- timeline validity
- caption synchronization
- render metadata
- regression changes
- continuity results supplied by upstream modules
- human-review checkpoints

## Scene evaluation

Each scene receives an explicit pass/fail result and error list.

This makes failures actionable rather than hidden.

## Regression

A snapshot records stable structural properties of a scene.

When a scene changes, snapshots can identify:
- duration changes
- layer changes
- animation changes

This is a lightweight regression mechanism. Future versions can add visual pixel/perceptual snapshots.

## Render validation

A successful renderer process is not sufficient.

The output must satisfy expected:
- width
- height
- FPS
- non-empty duration

## Human review

Some content may require human approval.

Review checkpoints are explicit objects with:
- scope
- criteria
- status
- decision
- reviewer
- notes

A required pending or rejected checkpoint blocks the quality gate.

## Course-level quality gate

M60 aggregates scene, render and review failures.

`PASS` means the known automated and required review checks have passed.

`FAIL` means final delivery must stop.

## Important limitation

M60 does not independently prove scientific truth.

Domain correctness must come from the knowledge/reconciliation and domain-validation layers.

M60 verifies that required upstream validation has been executed and that production artifacts satisfy structural/technical contracts.
