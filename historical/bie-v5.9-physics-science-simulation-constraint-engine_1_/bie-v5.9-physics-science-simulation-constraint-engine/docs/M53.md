# M53 — Physics / Science Simulation & Constraint Engine

M53 is the scientific-integrity layer between mathematical visualization and animation.

## Why it exists

A visualization can look physically plausible while violating the model.

M53 therefore represents:
- physical laws
- conservation rules
- causal relationships
- units and dimensions
- hard and soft constraints
- simulation parameters
- initial conditions
- observables
- visual mappings

## Dimensional consistency

Equations can be checked for dimensional compatibility.

A mismatch is a quality-gate error.

## Constraints

Constraints are explicit and classified as:
- HARD — must not be violated
- SOFT — desirable but may be violated within a declared optimization policy

The current scaffold deliberately returns unresolved constraint checks as `PENDING_EVALUATION`; it does not pretend that a check passed without a trusted evaluator.

## Causality

Causal relations store:
cause → mechanism → effect

This helps the animation planner distinguish a meaningful causal change from decorative motion.

## Simulation

A simulation declares:
- variables
- parameters
- equations
- initial state
- time step
- number of steps
- backend integration method

The actual numerical solver can later be plugged in without changing the educational semantics.

## Observable-to-visual mapping

Simulation outputs should map to visual observables.

For example:

`velocity`
→ object position

`electric field`
→ vector arrows

`temperature`
→ scalar field representation

`charge density`
→ particle/field visualization

The mapping is semantic, not merely stylistic.

## Scientific integrity rule

**Plausible-looking is not equivalent to scientifically validated.**

M53 therefore keeps validation state explicit.

## Relationship to M52

M52 answers:

**How should the mathematical/scientific state be visualized?**

M53 answers:

**What states are physically allowed and how should they evolve?**

Together:

`Model → Valid State → Visualization → Animation`
