# M93 — Asset Specification, Dependency Graph & Production Contract Engine

M93 converts representation plans into executable production specifications.

## Asset specification

Every production unit receives a stable asset ID and explicit:
- asset type
- inputs
- outputs
- objective references
- requirements
- metadata

This allows assets to be reused and referenced across lessons.

## Dependency graph

Production is represented as a graph rather than an implicit sequence.

Examples:

`source fragment → explanation → visual plan → scene → narration → final composition`

Dependencies are explicit and can later be scheduled as a DAG.

## Production contract

A contract specifies what a renderer or generator must produce.

It can include:
- inputs
- outputs
- renderer class
- timing
- interaction
- accessibility
- validation
- constraints

The renderer class is intentionally abstract.

For example, a contract can say `2D_ANIMATION` without forcing Remotion, SVG, Canvas or another implementation.

## Timing

Timing requirements can specify:
- start
- duration
- frame rate
- synchronization references

These can later feed the temporal planning system.

## Interaction

Interactive assets can declare:
- inputs
- states
- events
- outputs

This creates a stable contract between educational logic and UI/runtime implementation.

## Accessibility

The production contract can carry:
- captions
- alt text
- keyboard support
- contrast requirements
- transcripts

Accessibility is therefore part of the asset specification rather than a final afterthought.

## Validation

Every production contract should state how its output will be validated.

This is critical for automated generation.

Possible future checks include:
- schema validation
- visual constraints
- timing consistency
- source/provenance checks
- interaction state coverage
- pedagogical alignment
- render success

## Graph-based production

M93 creates the foundation for parallel production.

Independent assets can be generated concurrently.

Dependent assets wait for their required inputs.

This becomes important for full books/courses containing thousands of assets.

## Relationship

M92 decides the representation.

M93 defines the exact asset and production contract.

M94 can turn these contracts into a Production DAG, Scheduling, Caching & Incremental Build Engine.
