# M16 — Remotion Renderer Contract

M16 creates the stable boundary between pedagogy and video rendering.

## Scene DSL

Every scene declares:
- scene_id
- scene type
- duration
- learning objective
- visual type and instructions
- assets
- narration
- on-screen text
- equations
- animation actions
- camera behavior
- transition
- emphasis
- source evidence
- optional checkpoint

## Why an intermediate DSL

The LLM should not repeatedly invent React/Remotion implementation.
It produces a deterministic scene specification.

A renderer library translates that specification into Remotion components.

## Timing

Narration length provides an initial duration estimate. Minimum duration guards prevent unreadably short scenes. A later audio/TTS pass can replace estimates with measured audio duration.

## Evidence

Every scene inherits evidence_refs from the learning unit so generated video content remains traceable to the book.

## Renderer architecture

Scene DSL
→ scene normalizer
→ asset resolver
→ narration/TTS timing
→ Remotion component registry
→ Composition
→ render
→ MP4

## Component registry

Future renderer components should include:
DefinitionScene, ProcessScene, EquationScene, DiagramScene, ChartScene,
TableScene, ApplicationScene, WorkedExampleScene, CheckpointScene, RecapScene.

The same pedagogical scene can therefore be rendered consistently across an entire course.
