# M72 — Course Knowledge & Asset Memory / Reuse Engine

M72 gives BIE persistent memory for validated educational and production artifacts.

## What is stored

The memory model can store:
- canonical concepts
- explanations
- solved examples
- visual assets
- animation specifications
- narration fragments
- assessment items
- rendered artifacts

## Versioning

Records have explicit versions.

A changed explanation, visual or asset can therefore coexist with earlier versions instead of silently overwriting history.

## Provenance

Records retain:
- source references
- derivation references
- generator identity
- validation identity

This keeps reused material traceable.

## Semantic reuse

A new lesson can search memory for semantically related records.

Reuse decisions have three reference outcomes:
- `REUSE`
- `ADAPT`
- `REGENERATE`

High-confidence matches can be reused directly.

Near matches can be adapted.

Weak matches should be regenerated.

The thresholds are configurable and are not a claim about any specific embedding model.

## Lineage

Artifacts can form a dependency/lineage graph.

For example:

`Source concept → explanation → visual spec → narration → scene → render`

This allows downstream artifacts to be located when an upstream record changes.

## Invalidation

If a canonical record is invalidated or materially changed, affected downstream artifacts can be marked for rebuild.

The system should never silently reuse an invalidated artifact.

## Domain independence

This is not a Physics-only memory system.

The same memory architecture can store:
- mathematics
- physics
- chemistry
- biology
- history
- economics
- programming
- professional training
- other structured educational domains

## Critical boundary

Memory is not automatically truth.

Only validated/canonical records should be promoted into trusted reusable knowledge.

Semantic similarity alone must never override source evidence or domain validation.

## Relationship to M71

M71 orchestrates course production.

M72 reduces repeated work by providing persistent, versioned reusable knowledge and production artifacts.
