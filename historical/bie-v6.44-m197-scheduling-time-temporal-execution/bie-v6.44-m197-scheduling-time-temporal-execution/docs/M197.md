# M197 — Scheduling, Time & Temporal Execution Layer

M197 defines vendor-neutral temporal contracts for scheduling and time-aware execution.

## Clock abstraction

A clock identifies the time source and timezone. A monotonic flag indicates whether elapsed-time calculations should use a monotonic source.

The abstraction does not prescribe a specific clock implementation.

## Schedules and intervals

Schedules can specify start/end bounds, recurrence and timezone. Intervals express repeated execution periods with optional finite counts.

## Calendars

Calendars carry timezone, business-day hints and holiday dates.

## Deadlines

Deadlines define a due time, optional grace period and policy:

```text
FAIL
WARN
EXTEND
```

## Timeouts

Timeouts define a duration and action:

```text
CANCEL
RETRY
ESCALATE
```

## Temporal retries

Retry policy supports fixed, linear and exponential backoff.

## Temporal windows

Windows define bounded time ranges with independently configurable inclusive boundaries.

## Temporal state

A resource state can carry effective and optional expiry timestamps, enabling time-aware state evaluation.

## Audit and observability

Temporal events capture scheduling/execution lifecycle, while metrics expose lateness and execution duration.

## Important boundary

M197 does not implement cron, Quartz, Airflow, Temporal, a distributed scheduler, a timezone database, or a wall-clock synchronization protocol. It provides portable temporal semantics and integration contracts.
