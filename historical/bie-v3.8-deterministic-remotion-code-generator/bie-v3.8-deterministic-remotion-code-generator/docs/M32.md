# M32 — Deterministic Remotion Code Generator

M32 is the execution bridge from validated Scene DSL to React/Remotion source.

## Pipeline

Scene DSL
→ Intermediate Representation (IR)
→ stable keys
→ timeline contract
→ React/Remotion component source
→ render metadata

## Determinism

Semantic scene/layer identities are converted into stable keys. This is important for:
- repeatable renders
- asset reuse
- debugging
- incremental regeneration
- comparing revisions

## Timing

The generated IR retains AUDIO_DRIVEN timing. It deliberately does not turn the architecture back into arbitrary fixed-duration scenes.

The example root generator uses a placeholder duration only as scaffolding; production compilation must substitute duration from finalized audio alignment before rendering.

## Separation of concerns

The code generator does not decide:
- what the student should learn
- pedagogical order
- what a scene should contain
- which assets are pedagogically appropriate

Those decisions belong to M27–M30.

M32 translates an already validated specification into executable rendering structure.

## Production hardening still required

A production renderer should add:
- real Remotion primitives/components rather than placeholder DOM primitives
- asset loaders
- font management
- audio files and exact frame conversion
- transition compiler
- camera compiler
- error boundaries
- render manifests
- caching/incremental compilation
- visual regression tests
- deterministic retry behavior
