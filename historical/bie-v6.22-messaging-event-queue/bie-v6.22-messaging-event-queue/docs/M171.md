# M171 — Messaging, Event Bus & Queue Layer

M171 provides storage- and broker-neutral contracts for asynchronous communication.

## Topics

Topics represent event streams and can declare:
- retention
- partitions
- ordering requirements

## Queues

Queues provide command/task delivery contracts with:
- visibility timeout
- maximum attempts

## Events

Events contain:
- event ID
- event type
- payload reference
- tenant
- correlation ID
- causation ID
- version

Payloads can remain in M170 object storage instead of being embedded in messages.

## Commands

Commands represent requested actions and can transition from:

```text
READY
  ↓
ACCEPTED
```

Commands are distinct from events: commands request work; events report facts.

## Consumer groups

Consumer groups provide scalable consumption over topics.

Concurrency is explicit at the contract level.

## Delivery semantics

Reference modes:

```text
AT_MOST_ONCE
AT_LEAST_ONCE
EXACTLY_ONCE
```

The actual broker adapter must provide the selected guarantee.

## Retry

Retry policies support:

```text
FIXED
LINEAR
EXPONENTIAL
```

## Dead-letter handling

Messages can move to a dead-letter destination after an attempt threshold or matching configured reason codes.

## Idempotency

An idempotency key combines:
- scope
- operation
- key

This is critical because at-least-once delivery can produce duplicate deliveries.

## Scheduled delivery

Messages can be scheduled for a future delivery time with an explicit timezone.

## Observability

Messaging operations record:
- operation
- status
- latency
- attempt

This feeds M150 telemetry.

## Relationship

```text
M161 Workflows
     ↓
M171 Commands / Events
     ↓
Broker / Queue Adapter
     ↓
Consumers
     ↓
M167 Persistence / M170 Objects
```

M163 authorization and M164 policy remain applicable to producers and consumers.

M155 audit/compliance can consume relevant event streams.

M168 cache invalidation can subscribe to domain events.

## Important boundary

The reference layer does not implement Kafka, NATS, RabbitMQ, SQS, Pub/Sub, a broker cluster, distributed locks, consumer rebalancing or exactly-once infrastructure.
