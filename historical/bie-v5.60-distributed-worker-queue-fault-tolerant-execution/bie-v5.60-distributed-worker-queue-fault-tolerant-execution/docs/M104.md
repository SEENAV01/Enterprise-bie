# M104 — Distributed Worker, Queue & Fault-Tolerant Execution Layer

M104 turns the M103 schedule into a resilient distributed execution system.

## Persistent queues

Jobs live in explicit queue state rather than only in transient scheduler memory.

This supports recovery after process or worker failure.

## Workers

Workers advertise capabilities.

A dispatcher can therefore select workers compatible with a job's requirements.

Examples:
- GPU availability
- tool availability
- memory capacity
- renderer capability

## Leases

A worker receives a time-bounded lease for a job.

If the worker disappears and the lease expires, the job can become eligible for recovery.

Leases reduce ambiguous ownership.

## Heartbeats

Workers can report heartbeat timestamps.

A production implementation can use heartbeat expiry to detect unhealthy workers and allow lease recovery.

## Retry policy

Retries are explicit.

A policy can define:
- maximum attempts
- backoff
- retryable errors

Permanent failures should not be retried indefinitely.

## Idempotency

A deterministic execution key can be derived from:
- job identity
- input versions
- parameters

Before applying an effect, the system can check whether that execution key has already completed.

This is critical because distributed systems may legitimately execute a job more than once after uncertain failures.

## Checkpointing

Long jobs can write checkpoints containing:
- progress
- intermediate artifacts
- state digest

Recovery can resume from the latest valid checkpoint instead of restarting from zero.

## Exactly-once effect

True exactly-once execution is difficult across arbitrary external systems.

M104 therefore targets **exactly-once effects where practical**, using idempotency, durable state and controlled commit boundaries.

The architecture does not falsely claim that every external side effect can be made exactly-once.

## Failure flow

```text
Worker executes
      ↓
Heartbeat stops
      ↓
Lease expires
      ↓
Job recovered
      ↓
Checkpoint inspected
      ↓
Retry / resume
      ↓
Idempotency check
      ↓
Commit result
```
