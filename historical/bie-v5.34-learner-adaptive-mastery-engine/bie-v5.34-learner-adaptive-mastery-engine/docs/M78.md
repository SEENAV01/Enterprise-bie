# M78 — Learner Model, Adaptive Sequencing & Mastery Engine

M78 adds the learner side of BIE.

## Separation of concerns

Canonical knowledge and pedagogical plans remain immutable source-side structures.

Learner state is a separate runtime layer.

This prevents one learner's performance from changing the underlying course.

## Learner state

The model can track:
- objective
- mastery status
- score
- attempts
- evidence
- misconception signals

## Adaptive decisions

Reference decisions:
- `ADVANCE`
- `REVIEW`
- `REMEDIATE`

A mastered objective can be advanced past when prerequisites allow.

A weak result triggers review.

Detected misconceptions can trigger targeted remediation.

## Mastery

Mastery is evidence-driven rather than inferred from video completion.

The threshold is configurable.

Production systems can later replace the simple threshold with richer mastery models such as Bayesian knowledge tracing, item-response models or custom domain rules.

## Prerequisite safety

Adaptation does not override prerequisite relationships from M77.

A learner may skip redundant presentation, but the system should not silently assume mastery of an unmet prerequisite.

## Explainability

Every adaptive decision carries a reason.

This is important for debugging, teacher controls and learner trust.

## Domain independence

The engine is domain-agnostic.

The same architecture can personalize mathematics, physics, programming, languages, professional training and other domains.

## Relationship to previous modules

M77 defines the pedagogical sequence.

M78 executes an adaptive learner path through that sequence.

M72 stores reusable content.

M74 validates content.

M73 manages source/content change impact.

## Important boundary

M78 is not the learner-facing UI itself. It produces learner state and decisions consumed by the learning-experience layer.
