# M36 — Evidence Retrieval + Claim Verification Engine

M36 is the evidence layer for M35's higher-knowledge expansion.

## Core principle

A candidate external claim is not automatically educational truth.

The pipeline is:

Candidate
→ Retrieval Request
→ Source Ranking
→ Claim Extraction
→ Claim-level Evidence
→ Contradiction Detection
→ Verification
→ Teaching Gate

## Source hierarchy

The default preference is:
1. Primary sources
2. Standards bodies
3. Government sources
4. Academic reviews
5. Universities
6. Professional organizations
7. Textbooks
8. Reference works
9. News
10. General web

The hierarchy is a default ranking, not an absolute truth rule. A source is evaluated for the specific claim.

## Claim-level evidence

Evidence is attached to a specific claim rather than merely saying "this website supports the topic."

The record can preserve:
- source
- passage
- support/contradiction relation
- locator
- optional quote

## Contradictions

If credible evidence contains conflicting claims, the packet becomes CONFLICT rather than silently selecting one.

This blocks automatic teaching until review/resolution.

## Freshness

Time-sensitive claims can require publication/version checks. The freshness module records whether the source is current/relevant, older, or unknown.

## Teaching gate

Only VERIFIED packets pass automatically.

UNVERIFIED and CONFLICT states require additional evidence or human/reasoning review before the material enters the curriculum.

## Retrieval-provider boundary

M36 defines the retrieval and verification contract but deliberately does not hard-wire one web/search provider. This allows the system to use approved search APIs, academic databases, source repositories or other retrieval systems.
