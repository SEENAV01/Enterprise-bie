# M123 — Configuration, Versioning & Feature-Flag Layer

M123 makes runtime configuration an explicit, versioned and reproducible part of the system.

## Why configuration must be versioned

A build can change because of:
- model version
- generation parameters
- render settings
- voice configuration
- quality thresholds
- policy versions
- feature flags
- experiment assignments

Without a configuration reference, reproducing or explaining an artifact becomes difficult.

## Immutable snapshots

A configuration snapshot contains:
- config ID
- version
- schema version
- values
- metadata
- deterministic digest

The digest is derived from canonicalized configuration content.

## Semantic versioning

The reference implementation supports major, minor and patch versions.

The versioning policy itself can be extended for platform-specific compatibility rules.

## Feature flags

Feature flags explicitly control whether a capability is enabled.

Rules can evaluate context to select behavior.

Flags should be included in reproducibility references when they can affect an artifact.

## Experiments

Experiment assignments use deterministic hashing of experiment and subject identity.

This means the same inputs can receive the same bucket without storing an arbitrary random decision.

Production experimentation systems may require stronger assignment, privacy and statistical controls.

## Compatibility

A compatibility check compares required configuration attributes against available values.

A mismatch produces explicit failures instead of silently proceeding.

## Reproducibility reference

The build can carry:

```text
Configuration
     +
Feature Flags
     +
Experiment Assignments
     ↓
Reproducibility Reference
```

This reference can be attached to M114 build records and M116 audit events.

## Relationship

M114 provides reproducible build identity.

M122 uses configuration fingerprints to avoid unsafe cache reuse.

M123 makes those configuration inputs explicit and versioned.

## Important boundary

A configuration snapshot is not itself a secrets store.

Secret values should remain behind M118's protected secret references.
