# M10 — LLM Book Understanding Engine

M10 replaces the earlier keyword-only scaffold with a production contract for model-based extraction.

## Core model task

For every book unit, the model must produce:
- source-grounded claims
- evidence IDs
- What/Why/How/When/Where/Who
- derivations
- applications
- dependencies
- uncertainty
- confidence
- separate higher-knowledge candidates

## Evidence-first rule

A claim is not source-derived merely because the model believes it.
It must point back to evidence.

Recommended internal representation:

Claim
→ evidence span
→ page/chunk
→ source document

## Long books

The pipeline is hierarchical:

PDF
→ page/layout extraction
→ semantic chunks
→ batched model extraction
→ unit-level consolidation
→ cross-unit dependency inference
→ global consistency pass
→ scene planning

Never send an entire long textbook blindly in one prompt.

## Contradictions

Contradictions and ambiguities are explicitly represented as REVIEW states.
The engine must not silently reconcile conflicting statements.

## Higher knowledge

Knowledge outside the book is kept in a separate field and labelled `EXTERNAL_RESEARCH` when actually researched.

Potential higher knowledge should NOT automatically be asserted as fact. It first becomes a candidate for retrieval/verification.

## Model training strategy

Do not start by training a foundation model from scratch.

Use a strong model for structured extraction and build a high-quality dataset of:
document span → expected JSON → evidence → question matrix → dependencies → scene plan.

Then:
1. evaluate baseline prompting
2. create error taxonomy
3. fine-tune a smaller model for stable extraction/classification
4. use retrieval/tool calls for external knowledge
5. keep the strongest model as a verifier/judge where needed

This separates expensive reasoning from repeatable extraction.

## Accuracy gates

A unit should fail or enter review if:
- evidence is missing
- source reference is missing
- confidence is invalid
- contradiction is unresolved
- external knowledge is mixed into source-derived claims

M10 is therefore the bridge from a prototype pipeline to a real BIE model architecture.
