# M112 — Structured Authoring / Intermediate Representation Layer

M112 introduces the canonical authoring representation between content/learning intent and renderer-specific production.

## Why an IR

Without an intermediate representation, each renderer becomes coupled to:
- source semantics
- learning logic
- layout
- timing
- asset dependencies
- interaction logic

That makes renderer changes expensive.

The IR separates authored intent from rendering implementation.

## Hierarchy

```text
Document
  ↓
Lesson
  ↓
Scene
  ↓
Components
  ↓
Timeline + Layout + Semantic Bindings
```

## Components

Reusable components expose:
- component identity
- component type
- properties
- semantic references
- children

Examples:
- text
- equation
- diagram
- image
- chart
- object
- camera
- audio
- interactive control

Renderer-specific implementations can map these component types to native primitives.

## Timeline

Temporal behavior is explicit.

Timeline items reference components and declare start/duration and optional animation parameters.

This enables the same authored scene to be rendered into different temporal targets.

## Layout

Layout constraints are represented separately from renderer code.

This allows a renderer adapter to translate constraints into:
- CSS
- SVG geometry
- canvas coordinates
- video composition coordinates
- other target systems

## Semantic bindings

A component can bind to a semantic reference.

For example:

```text
semantic: force.magnitude
        ↓
component: force-vector.label
```

If the underlying semantic value is updated, the binding can be resolved without rewriting the component definition.

## Transformation passes

IR can pass through versioned transformations before rendering.

Examples:
- accessibility expansion
- localization
- responsive layout
- renderer lowering
- optimization
- simplification
- platform adaptation

The transformation history remains explicit.

## Multiple renderers

The target architecture becomes:

```text
                 Canonical IR
                      ↓
       ┌──────────────┼──────────────┐
       ↓              ↓              ↓
   Video Renderer  Web Renderer  Interactive Renderer
       ↓              ↓              ↓
      MP4            HTML/SVG       App/Simulation
```

The same authored representation can therefore serve multiple delivery formats.

## Relationship

M110 defines multi-modal representation abstraction.

M111 defines representation and generation planning.

M112 defines the canonical structured representation that downstream renderers consume.

M101–M104 remain responsible for safe, scheduled and reliable execution of generated production work.

## Critical boundary

The IR is **not** the final video code.

It is the stable intermediate contract between semantic/authoring logic and renderer implementations.

This makes renderer replacement, multi-target publishing and future platform expansion substantially easier.
