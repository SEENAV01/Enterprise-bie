# M141 — Distributed Worker Runtime & Execution Sandbox Layer

M141 is the execution substrate beneath the M140 orchestration layer.

## Worker registration

Workers expose:
- worker ID
- capabilities
- resources
- execution environment
- status

This lets the scheduler reason about where a task can run.

## Capability and resource matching

A task can declare required capabilities and resources.

Examples:

```text
Capability: REMOTION
Capability: GPU
CPU: 4
Memory: 16 GB
```

A worker is eligible only when it satisfies the declared requirements.

## Dispatch

The dispatch contract records:
- task
- selected worker
- requirements
- resources
- dispatch state

The reference implementation selects the first eligible worker. Production scheduling should add load-aware placement, locality, quotas and fairness.

## Sandbox

A sandbox records:
- sandbox ID
- execution image
- resource limits
- artifact mounts
- network policy

The reference policy supports DENY or ALLOWLIST network modes.

## Artifact mounts

Artifacts can be mounted read-only or read-write.

Read-only should be the default for immutable inputs.

## Timeouts

Task execution can have an explicit timeout and optional grace period.

## Heartbeats and health

Workers periodically emit heartbeats.

Health can be derived from the age of the latest heartbeat.

```text
Worker
  ↓
Heartbeat
  ↓
Fresh?
 ├── YES → Healthy
 └── NO  → Suspect
```

## Structured task results

Workers return a structured result containing:
- task ID
- worker ID
- status
- outputs
- error
- metrics

This result feeds back into M140 execution state and M134 observability.

## Relationship

M140 decides **what task runs next**.

M141 decides **where and under what execution constraints the task runs**.

```text
DAG Scheduler
     ↓
Worker Selection
     ↓
Sandbox
     ↓
Execution
     ↓
Result
```

M137 provenance can record the worker/image/environment used.

M139 media tasks can run on specialized workers.

## Important boundary

The reference layer defines contracts and metadata. It does not provide OS-level isolation, container runtime enforcement, GPU scheduling, secret injection or a production worker network. Those require infrastructure such as containers/VMs, orchestration platforms and secure credential services.
