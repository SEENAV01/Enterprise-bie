# M83 — Spatial Layout, Composition & Visual Constraint Solver

M83 turns semantic visual objects into a spatial composition.

## Why this layer exists

M81 defines what visual objects and relationships exist.

M82 provides reusable components and style.

M83 determines how those objects occupy the visual space.

This prevents downstream renderers from making arbitrary placement decisions.

## Constraint model

Reference constraints include:
- alignment
- centering
- vertical/horizontal stacking
- containment
- spacing
- overlap avoidance
- anchors
- safe-area constraints
- following
- semantic focus

Constraints have priority levels so production systems can distinguish hard requirements from preferences.

## Hierarchy

Visual hierarchy records importance and parent/child relationships.

This can drive:
- size allocation
- z-order decisions
- attention priority
- camera focus
- responsive simplification

## Collision and safe-area validation

The reference solver detects:
- missing targets
- object overlap
- objects outside safe areas

A production solver can later replace validation with a full constraint optimization engine.

## Camera and framing

Camera specifications are explicit.

Possible modes can include:
- static
- follow
- focus
- zoom
- pan

The exact motion remains a downstream temporal concern.

## Responsive composition

Rules can adapt compositions to different:
- aspect ratios
- viewport sizes
- display modes

This is useful when the same educational content targets landscape video, mobile screens or interactive web experiences.

## Renderer independence

M83 produces spatial intent and validation results.

It does not generate renderer-specific positioning code.

## Relationship

M81 → visual grammar.

M82 → assets, styles and reusable components.

M83 → spatial composition.

The next layer can add temporal planning so spatial states become a coherent sequence over time.
