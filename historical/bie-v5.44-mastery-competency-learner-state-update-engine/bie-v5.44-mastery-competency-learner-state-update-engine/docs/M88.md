# M88 — Mastery, Competency & Learner State Update Engine

M88 turns individual learning events into a longitudinal learner state.

## Why a learner state is needed

A single percentage cannot adequately represent:
- what the learner knows
- which objective is mastered
- which prerequisite is weak
- which misconception remains active
- how confident the evidence is
- whether performance is improving or declining

M88 therefore keeps these dimensions separate.

## Evidence

Assessment, interaction, practice and diagnostic events can become evidence events.

Evidence can carry:
- objective
- concepts
- score
- correctness
- confidence
- diagnosis references
- timestamp

## Objective mastery

Objective-level evidence is aggregated independently.

The reference implementation demonstrates confidence-weighted score aggregation.

A production mastery model can later incorporate:
- recency
- repeated attempts
- item difficulty
- evidence diversity
- forgetting
- calibration
- Bayesian or psychometric models

These are extension points, not assumptions of this layer.

## Competency

Competencies can aggregate multiple objectives and concepts.

This prevents a course from treating every objective as an isolated skill.

## Prerequisite readiness

Prerequisite relationships can influence readiness for downstream objectives.

A learner can therefore be:
- proficient on a current objective
- but not ready for an advanced dependent objective

## Misconception risk

Misconceptions remain a separate state dimension.

A learner may have high general performance while still carrying a specific misconception risk.

## Longitudinal history

The state retains a history channel so later systems can reason over changes rather than only the latest answer.

## Important principle

M88 does not collapse the learner into one number.

Instead:

`Evidence → Objective mastery + Competency + Prerequisite readiness + Misconception risk + Confidence + History`

## Relationship

M86 → assessment evidence.

M87 → diagnosis/remediation.

M88 → persistent learner state.

M78 can consume this state to select the next learning action.
