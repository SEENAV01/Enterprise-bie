# M133 — Policy Decision, Governance & Configuration Control Plane

M133 creates a common control plane for policies and configuration that influence BIE behavior.

## Policy registry

Policies are stored under explicit IDs and versions.

```text
routing-policy
 ├── 1.0
 ├── 1.1
 └── 2.0
```

A policy can move through lifecycle states such as DRAFT and APPROVED.

## Effective configuration

Policies can be composed from:

```text
Base Policy
    +
Environment Overlay
    +
Tenant Overlay
    ↓
Effective Policy
```

This allows controlled differences between environments without duplicating the entire policy.

## Policy decision

A policy evaluator returns an explicit decision and identifies the policy/version used.

This creates a stable reference for audit and debugging.

## Simulation

Before activating a policy, the system can run representative contexts through the old and new policies.

The resulting decision diff can expose behavioral changes:

```text
Old → ALLOW
New → DENY
```

This is especially useful for routing, security, lifecycle and workflow policies.

## Change control

A policy change can carry:
- request ID
- source version
- target version
- author
- reason
- approval requirement
- approver
- status

Critical production changes can therefore require explicit approval.

## Feature/config flags

Feature flags allow controlled activation by environment and rollout configuration.

They should remain separate from permanent policy rules.

## Rollback

A rollback is an explicit record from the current policy version to a known target version.

## Relationship

M132 establishes authorization primitives.

M133 governs the policies that define authorization, routing, lifecycle and workflow behavior.

M123 configuration versioning, M116 audit and M129 contract governance can all consume this control-plane model.

## Important boundary

The reference implementation is a governance model, not a distributed configuration service. Production requires atomic publication, consistency guarantees, access controls, audit persistence and safe rollout mechanisms.
