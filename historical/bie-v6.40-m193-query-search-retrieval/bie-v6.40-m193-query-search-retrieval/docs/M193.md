# M193 — Query, Search & Retrieval Abstraction Layer

M193 defines vendor-neutral contracts for querying governed resources.

## Query contract

A query identifies a resource and can carry:

- filters
- projection
- sort order
- pagination
- consistency hints

The abstraction deliberately avoids coupling the contract to SQL, GraphQL, a search engine, or a specific database.

## Filtering

Supported reference predicates:

```text
EQ
NE
GT
GTE
LT
LTE
IN
CONTAINS
PREFIX
```

Implementations may add operators through extensions.

## Sorting

Sort order is explicit and supports ascending or descending direction.

## Pagination

Pagination supports either a cursor or an offset, but the reference contract prevents both from being supplied simultaneously.

## Projection

Projection limits returned fields and defaults to all fields when unspecified.

## Indexes

M193 models standard, unique and full-text index declarations. Index creation/management remains an implementation concern.

## Consistency

Query callers can express a consistency hint:

```text
EVENTUAL
SESSION
BOUNDED
STRONG
```

The storage/search implementation decides whether and how it can satisfy that hint.

## Result envelope

Results carry items, an optional continuation cursor, optional total and a partial-result flag.

## Audit and observability

Retrieval operations produce audit events and metrics including latency and result count.

## Relationship

```text
M187 → Policy / Decision

M191 → Data Governance / Lineage
```

## Important boundary

M193 does not implement a database, query optimizer, search engine, SQL parser, or distributed execution planner. It establishes portable request/result semantics and integration points.
