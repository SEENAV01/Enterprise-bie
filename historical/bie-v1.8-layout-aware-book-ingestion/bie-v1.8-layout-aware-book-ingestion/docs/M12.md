# M12 — Layout-Aware Book Ingestion

M12 upgrades the BIE input layer from plain text to document structure.

## What is retained

For every page/block:
- page number
- block type
- reading order
- heading hierarchy
- bounding box when available
- figure/table/equation asset references
- parent heading

## Why this matters

A textbook's meaning is not only its paragraphs. A diagram can define a process, a table can contain the evidence for a comparison, and an equation can encode a derivation.

The BIE therefore treats these as first-class evidence objects.

## Hierarchical understanding

PDF
→ pages
→ blocks
→ headings
→ sections
→ chapters
→ chapter-level consolidation
→ book-level graph

This prevents a long book from becoming an unordered bag of chunks.

## Asset handling

- Tables: parse + verify against the page
- Figures: vision interpretation + source grounding
- Equations: math extraction + verification
- Captions: linked to their figure/table
- Lists: preserve item/order structure

## OpenAI integration

The current OpenAI API model catalog supports text and image inputs and the Responses API; this makes the next vision/table/equation extraction layer feasible. The implementation should still preserve the document IR and evidence IDs before sending content to a model.

## Accuracy rule

The model may interpret a figure or table, but the resulting claim must retain a link to the original page/block/asset. Interpretation is not allowed to erase provenance.
