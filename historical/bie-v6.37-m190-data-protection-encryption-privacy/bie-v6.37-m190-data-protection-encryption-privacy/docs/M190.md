# M190 — Data Protection, Encryption & Privacy Policy Layer

M190 defines vendor-neutral data protection contracts.

## Classification

Supported levels:

```text
PUBLIC
INTERNAL
CONFIDENTIAL
RESTRICTED
```

Classification drives downstream protection requirements.

## Encryption

Encryption policies can require a specific algorithm and separately declare at-rest and in-transit protection.

M189 supplies the key lifecycle boundary; M190 defines the data-protection requirement.

## Masking

Masking strategies:

```text
REDACT
PARTIAL
HASH
TOKENIZE
```

Policies identify fields that require transformation.

## Tokenization

Tokenization records identify protected fields and an external vault reference. Reversibility is explicit.

## Retention

Retention policies define duration, deletion behavior and legal-hold state.

Deletion modes:

```text
DELETE
ANONYMIZE
ARCHIVE
```

A legal hold blocks normal deletion.

## Privacy purpose

A privacy policy records the intended purpose, optional lawful basis, minimization requirement and consent requirement.

## Data handling

Handling policies can constrain geographic locations and processors for a classification.

## Access boundaries

M188 authorization can use a data-protection boundary to restrict actions against sensitive data.

## Audit and observability

Protection events capture principal, data type, operation and status. Metrics expose classification and operation state.

## Relationship

```text
M188 → Identity / Authorization
M189 → Secrets / Keys
M190 → Data Protection / Privacy
M150 → Audit / Observability
```

## Important boundary

M190 does not implement a particular privacy regulation, DLP vendor, tokenization vault, encryption library, or legal interpretation. It provides explicit policy contracts for those integrations.
