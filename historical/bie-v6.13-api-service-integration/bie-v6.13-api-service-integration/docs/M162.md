# M162 — API, Service Contract & Integration Boundary Layer

M162 defines stable boundaries between BIE services and external systems.

## Request / response envelopes

Every service interaction can carry:
- request ID
- service
- operation
- tenant context
- idempotency key
- schema version

Responses preserve the request identity and expose status/data/error.

## API contracts

An API contract declares:

```text
Service
Operation
Method
Path
Request Schema
Response Schema
Version
```

This makes service boundaries explicit and machine-readable.

## Schema evolution

Schemas have explicit versions and a compatibility policy.

The reference layer models `BACKWARD` compatibility as the default example.

Supported conceptual modes:

```text
BACKWARD
FORWARD
FULL
NONE
```

The helper does not implement a full schema-diff engine.

## Service discovery

Services can publish endpoints with address, port and protocol.

Production discovery can be backed by DNS, a registry or an orchestrator.

## Health / readiness

Liveness answers whether a process is alive.

Readiness answers whether it should receive traffic.

Dependencies can be listed as part of the health contract.

## Idempotent APIs

For operations that may be retried, an idempotency key identifies the logical request so the same side effect is not performed repeatedly.

This complements M159 message idempotency and M160 state-transition idempotency.

## Integration adapters

External providers are isolated behind adapter contracts containing provider, protocol, timeout and retryability.

This prevents provider-specific details from leaking into core workflow logic.

## Contract testing

Consumer/provider compatibility can be represented as explicit contract tests.

```text
Consumer
   ↓
Expected Contract
   ↓
Provider
   ↓
Contract Test
```

## Relationship

```text
M159 Messaging
      ↓
M160 State
      ↓
M161 Workflow
      ↓
M162 API Boundary
      ↓
External Services / Providers
```

M150 correlation IDs support request tracing.

M151 reliability covers endpoint health.

M152 security controls access to APIs.

M157 resource governance constrains service resources.

## Important boundary

The reference implementation does not provide a production API gateway, service mesh, DNS registry, OpenAPI compiler, schema registry, external provider SDK or network server.
