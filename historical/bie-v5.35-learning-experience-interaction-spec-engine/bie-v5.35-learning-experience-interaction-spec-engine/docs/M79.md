# M79 — Learning Experience & Interaction Specification Engine

M79 defines what the learner actually experiences during a lesson.

## Lesson contract

A lesson contract links:
- learning objectives
- interactions
- asset requirements
- accessibility requirements

This contract is consumed by downstream visual, audio, simulation and rendering systems.

## Interaction model

Supported reference interaction types include:
- explanation
- demonstration
- prediction
- exploration
- question
- practice
- simulation
- reflection
- assessment

The list is extensible.

## Feedback

Feedback is represented as explicit rules.

Feedback can be tied to:
- an answer
- a condition
- a misconception
- a response

Feedback can also trigger adaptive behavior through hooks.

## Learner controls

Controls are first-class objects.

Examples include:
- sliders
- toggles
- playback controls
- variable selectors

The contract describes the control; implementation belongs downstream.

## Adaptive hooks

Hooks connect M78 learner state to the experience.

Examples:
- mastery → advance
- failure → review
- misconception → remediation
- learner request → repeat

## Accessibility

Accessibility is part of the lesson contract rather than an afterthought.

The reference contract supports:
- captions
- transcripts
- keyboard access
- screen-reader support
- reduced-motion requirements

Production renderers can extend this with WCAG-specific checks and richer modality alternatives.

## Provenance

Interactions should retain objective, concept and source references.

This allows a generated interactive experience to remain traceable to its educational intent and source.

## Separation

M79 specifies the learning experience.

It does not prescribe:
- React implementation
- Remotion code
- exact animation timing
- specific audio assets

Those are downstream production concerns.

## Domain independence

The engine is domain-agnostic.
