# AUDIO H5 — bounded native narration pipeline and durable reuse

## Identity and boundary
Parent: BIE-AUDIO-H4-R1-005. The five H5 engineering corrections are derived from AUDIO-AUDIT-001-F03, not new original roadmap IDs. The original H4 source was unavailable; its recovery history remains intact. H5 adds an actual fixed local TTS -> SYNC -> dry narration MIX lane. It does not claim to complete AUDIO, all of F03, the wider repository, or BIE product acceptance.

The unchanged canonical dependencies are standalone snapshots at commit 16d4d87824e77db3565a231a332e7977d39d7117. The new source imports those actual worker, artifact and lease APIs. It does not replace them with lookalikes, invent a second orchestrator, or authorize GitHub writes. Current repository/Codex source must be compared before eventual integration.

## H5-001: source and runtime contract
`pipeline_contract.build_request` prepares the exact declared source through the existing batch001-144 or batch001-204 preparation adapters. It binds the original source, exact plan, source-reference set, run UUID, job ID, revision, signer ID, selected profile, limits and canonical API identity. Verification reconstructs the prepared plan instead of accepting a caller-supplied plan hash. Declared source references are not independent proof that a book or DIR artifact was authenticated.

Default budgets are 8 prepared segments, 6,000 spoken characters, 180 seconds of delivered audio, a 180-second native deadline, 32 MB per file and 64 MB for the nine-file bundle. Allowed maxima remain finite. Exceeding a budget rejects the run; no truncation or quiet voice substitution occurs. The durable job namespace is distinct from H3/H4 acoustic jobs. A different source under the same run/job/revision conflicts; use a new governed revision for changed content.

`pipeline_profile.probe_profile` hashes selected actual executables, BIE engine/adapter code, pinned canonical dependencies and provider/meter identities. It invokes a fixed no-input/no-synthesis namespace discovery operation because library paths may legitimately differ between the host and worker namespace. The namespace identities are not normalized away or replaced by host identities. Discovery is memoized only under freshly checked host/code/worker identity. It is NOT profile approval. An externally supplied trust policy must separately approve the exact fingerprint.

The profile includes canonical Linux policy with network namespace isolation, capabilities/seccomp checks, no procfs, 2 GB address-space limit, 300 CPU seconds, 64 MB per-file native limit, descriptor/process bounds, 256 MiB tmpfs and two selected worker slots. These are selected local worker policies, not fleet scheduling, whole-host attestation, a hostile-host defense guarantee, or a global resource budget. Shared service lock roots are required for shared concurrency limits.

## H5-002: actual native execution and source/clock replay
`pipeline_runtime.run_local_pipeline` stages only fixed code and a validated JSON request. It launches the unchanged canonical Linux worker with the fixed entrypoint. No request-supplied command, plugin path, network endpoint or private key is exposed to that entrypoint. No fallback uses an unisolated local subprocess if isolation fails.

Inside the worker, existing TimedEspeakProvider, TTSCache, prepare_sync, pause/timestamp/caption code, FFmpegMeter and mix_synchronized execute. The cache is private and ephemeral inside that one worker; the separate durable layer caches the complete verified run. The worker currently creates a dry narration mix: no external music/SFX stems or newly supplied animation anchors. Existing AUDIO source remains unchanged and still offers its historical component APIs.

Nine outputs are byte-bound: master.wav, source.wav, SOURCE_SYNC.json, MIX_CLOCK.json, MIX_RECEIPT.json, captions.vtt, captions.srt, ENGINE_EVIDENCE.json and PIPELINE_SUMMARY.json. The host restores the real SYNC object, verifies exact prepared source and current catalog/voice/meter identities, replays same-engine word marks and derived captions, checks MIX/source clocks, rejects nonempty dry-lane stem lists and validates every length/hash. Worker result.json separately binds nonce, operation, request and output inventory. Input and staged code are rechecked. Hardlinks, symlinks, nonregular files, missing/extra payloads and unexpected process proof are rejected.

Same-engine timing replay is useful exact-PCM engineering evidence. It is NOT independent acoustic pronunciation/alignment acceptance. H4's independent diagnostic lane remains available separately; H5 does not automatically promote its result or manufacture acceptance.

## H5-003: external executor authority
`pipeline_evidence.issue_execution` requires an explicit Ed25519 private key matching the external profile-approved executor policy before native execution. It signs the exact request identity, profile, complete validated process/isolation evidence and nine-file inventory under the distinct BIE-AUDIO-LOCAL-PIPELINE-EXECUTOR-V1 domain. There is no public sign-arbitrary-report API. Receipt verification checks current code/runtime, current key/profile authorization, validity/revocation, age/skew, request/source binding and actual delivered bytes.

Receipt timestamps use integer seconds. The public verification `now` parameter also supports finite fractional clocks from canonical lease APIs; boolean, nonfinite, negative or nonnumeric clocks are rejected. Expiration comparisons retain fractional precision. Key validity and receipt age are checked again on stored reuse. Hashes or a caller-rehashed manifest do not authorize a result. Signed executor evidence is not publisher authorship, a sound-quality certification, or whole-host attestation. Key rotation/custody services and production trust provisioning remain open.

## H5-004: canonical durability and leases
`PipelineArtifactStore` uses the original FileSystemCAS/SQLiteArtifactCatalog/DirectorArtifactIO and artifact envelopes. The parent chain is declared source.asset -> audio.pipeline.request -> audio.pipeline.execution. The source and request parents, producer, run ID, provenance, exact blobs, receipt and current external trust must all verify on load. Conservative store quotas are checked before publication. Content addressing provides integrity, not independent authenticity.

`PipelineCoordinator` adapts only validation and job namespace over the existing canonical lease/idempotency APIs. A current fenced owner is required to complete. Concurrent acquisition, source-revision conflicts, stale epochs, bounded retries and claim-complete/lease-incomplete recovery are tested. The inherited heartbeat stays active during native execution and CAS publication, with serialized renewal before final completion. A stale owner may leave immutable orphan blobs but cannot commit the accepted job result. Orphan garbage collection is not added.

A completed run can be reused by a fresh process with zero new native speech/timing/mix evaluations, after current signature/profile/source checks. Identity discovery may still run. This is whole-run durable reuse, not cross-book semantic reuse, segment-level durable cache lifecycle, exactly-once paid synthesis or distributed book scheduling. Paid neural calls are not sent, retried or treated as idempotent by this lane.

## H5-005: explicit technical export
The CLI supports probe, request, run and verify-export. Both --allow-technical-voice and --allow-review-output are required for run/export. Source/profile/trust are separate expected inputs. An output is published exclusively through a private service directory; existing targets are not overwritten. Exports add the request, profile and signed receipt plus OUTPUT_SHA256.json. The verifier does not trust that manifest as authority: it revalidates hashes, source/clock derivations and the external signature policy. The original MIX reader can consume the resulting MIX and source files.

A private key file must be a 32-byte owned regular file without symlink parents, hardlinks or group/world permissions. No private key, API credential, font, native binary or model weight is shipped. The synthetic benchmark makes a disposable test-only signer in a private temporary directory and deletes it after execution. Its exported public trust is historical test evidence, not deployable production approval.
