## Exact identity and source preservation — H2-001
`build_job(mixed, sync, policy)` validates the existing MIX/SYNC relationship, hashes the actual delivered WAV, and binds the MIX receipt, sample clock, SYNC receipt, prepared plan, pronunciation targets, individual voice/request identities, original/source spans, prepared readings and declared provider word events. Each job is revision/policy-bound. Dry source WAV hashes and actual signal presence are derived from preserved verified speech assets; they are not caller assertions.

One analysis job is bounded by default to 32 segments, 60 seconds per segment, 180 seconds total, 256 words per segment, 70 MB source bytes and a 180-second worker deadline. Policy maxima are typed and bounded; no overflow truncation is allowed. PCM is 16-bit RIFF WAV, mono or stereo, 8–96 kHz. The delivered waveform is never changed. The source/token correspondence retains Unicode codepoint offsets. English evaluation tokenization is separate from narration preparation; unsupported numbers/symbols are rejected rather than silently removed.

## Actual acoustic analysis — H2-002
The installed legacy `libpocketsphinx.so.3` C ABI, SphinxBase, CMU English acoustic model, dictionary, allphone language model, N-gram model and FFmpeg are pinned by exact file hashes plus implementation/runtime identity. No Python PocketSphinx package is required or downloaded at runtime. No PocketSphinx 5.1.1 execution is claimed. The adapter has been executed on this Linux x86_64 environment; the probe also searches an explicit ARM64 library directory, but ARM64 deployment was not tested.

Each full current scene/segment crop is evaluated independently of the producer's word timestamps. An analysis-only FFmpeg conversion makes mono 16 kHz PCM with no dithering. The three native searches are: expected-text-constrained word FSG, unconstrained allphone decoding, and unconstrained N-gram word recognition. Source-space word windows are derived from decoder frames on a declared 10 ms grid using explicit sample rounding. Provider boundaries are compared, not used to fabricate native windows or overwritten.

The word FSG is constrained by the expected reading and cannot prove that reading was correctly pronounced. The allphone and N-gram searches supply independent but error-prone evidence. Dictionary-variant phone edit distances and 150 ms / 45 percent diagnostic thresholds are triage heuristics, not calibrated accuracy or probability estimates. Confidence remains null. Word endings are not verified phonetic ground truth. All reports explicitly retain `pronunciation_verified=false`, `alignment_accepted=false`, and `calibration_status=NOT_ESTABLISHED`.

Language support is deliberately only `en` or `en-US` with the installed dictionary. Hindi, other languages, mixed-language utterances, IPA overrides, out-of-vocabulary readings and unresolved alignments produce explicit unsupported/blocked outcomes. Stereo cancellation during analysis is blocked rather than classified as source silence. Exact-zero delivered PCM is measured directly.

A fixed standalone launcher owns dependency bootstrap; production AUDIO modules do not import archival snapshots or modify import paths. The launcher verifies the five existing pinned DIR dependency files when using the standalone closure, and its own bytes enter the runtime fingerprint. The child is bounded by deadline, cancellation, output limits and OS CPU/address-space/file-size limits. This is not a hostile-code sandbox, isolated canonical kernel worker, or distributed job service. F03 remains open.

## Authenticated evaluator evidence — H2-003
`issue_evaluation` runs the native worker internally before signing; it is not an API for signing arbitrary caller-provided results. Ed25519 receipts are domain-separated, contain exact job/source/media bindings and the full measurement, and are accepted only against a separately supplied trust configuration. A receipt cannot introduce its own trusted key. Issuer role, key, revocation, approved runtime fingerprints, validity interval, maximum age, future skew, nested schemas and current content identities are all checked. Duplicate JSON keys, nonfinite values, bool-as-number metrics and modified acceptance flags reject.

A signature authenticates a configured local diagnostic issuer. It is not proof that the model is accurate, that the host is trustworthy, that an external production evaluator was used, or that the signing-key holder is honest. A malicious administrator able to alter both the trust file and signer is outside this local boundary. Production trust bootstrap, key custody, host attestation and durable audit authority remain F02/F03 work. Public hashes alone never replace signature verification.

Private keys are raw 32-byte Ed25519 seeds in owner-only regular files with no symlink following. They are not exported in public artifacts. Runtime CLI does not create or auto-trust a signer. Tests and the benchmark use explicitly labelled ephemeral test issuers only. New evidence expires after 600 seconds; archival receipts are historical evidence, not fresh authorization. Re-run evaluation for current verification; do not disable freshness to reuse an old result as current.

## Assessment and owned repair — H2-004
`assess_receipt` first authenticates and validates the receipt. Exact delivered silence is FAIL. When the verified original dry source contains signal, ownership is AUDIO/MIX and the proposed action is remix; when it also has no signal, ownership is AUDIO/VO and the proposed action is resynthesis. Native timing/phone/lexical disagreements are REVIEW because recognizer error and actual speech error have not been calibrated apart. Unsupported or incomplete evaluation is BLOCKED. Successful native execution still returns REVIEW and preserves all previous required pronunciation/alignment/render boundaries.

Existing QA pronunciation, missing-audio and synchronization checks receive the additional signed evidence and owned findings. Reload verification reauthenticates acoustic evidence rather than trusting a rehashed QA report. This does not independently authenticate all unrelated inherited QA observations, upstream source authority or caption authorship.

Repair requests identify the exact source references, current evidence, stage owner and unchanged reading. They declare dependent clocks/captions/animations/MIX/QA/render invalidation requirements but never claim kernel dispatch or durable invalidation was performed. No second orchestrator is introduced. `recheck_repair` requires new media, the same source/reading and diagnostic policy, a fresh current signed evaluation, and no time reversal. An old diagnostic item resolves only when the corresponding new segment was actually MEASURED and the old finding no longer occurs; missing/blocked evaluation cannot resolve it. Overall product repair acceptance stays false.

## Publication and native CLI — H2-005
`audio_acoustic.py` consumes an existing published MIX source; it does not recreate an example Scene IR or synthesize audio secretly. The CLI requires explicit local-diagnostic opt-in, a runtime snapshot, externally supplied trust and the matching private signer. Publication uses the existing QA publisher/lock helper, exclusive directories, temporary publication and manifests. Reload checks current source, signature, derived measurements/assessments/repair plan, augmented QA, nested manifests and caption exports against the bound caption artifact. File changes/additions/removals, unsafe paths, symlinks and stale evidence reject. These checks are not a new canonical CAS or publisher attestation framework.

Evaluate exit 3 means REVIEW; 2 means FAIL/BLOCKED. Read-only verify exit 0 proves scoped integrity/authentication at the time checked, never pronunciation or product acceptance. No cloud requests, GitHub writes, render calls or automatic repairs occur in this CLI.
