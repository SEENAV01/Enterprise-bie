# COMP H3 bounded hardening contract

This extends H2. The task registry is established before implementation from the H2 re-audit. Five tasks address layer-space frame coverage, content-fit evidence, explicit reduced motion, host identity/isolated equation production and checked entry-path adoption. Original source-only QA APIs remain versioned diagnostic paths. They are not sufficient to enter real rendering.

## H3-001 — Frame-space gate

Every integer frame in [0, ceil(duration_ms * fps / 1000)) is evaluated. Supported H2 transforms are composed in actual nested wrapper order about box centers. Visibility comes from the product of opacity tracks; reveal is conservatively a full box. Convex-box separating-axis checks reject undeclared intersections; touching boundaries are allowed. Outside-viewport corners are rejected. The gate deliberately does not infer ink bounds, transparent cutouts, z-order teaching intent or between-frame continuous paths. Work budgets are fail-closed, never sampled into a pass. Intentional overlap requires exact element pairs, explicit source/reasoning-bound justification and remains visible in the receipt. Intentional offscreen cropping is not silently accepted.

## H3-002 — Content-fit observations

Finite measurements must cover each expected element at every rendered frame and bind to the exact generated manifest, scene, viewport and frame rate. Negative dimensions, duplicate/missing records, stale identity, browser errors and incomplete font readiness block. Visible text/legend rectangles must remain within their owner and viewport; body and math em sizes must meet an explicit technical pixel floor. The validator does not silently shrink or delete content. It reports browser test-bridge evidence distinctly; that evidence can never authorize a real Remotion/render or learning-quality pass.

## H3-003 — Reduced-motion selection

Selection is a compile-time option (standard/reduced), never an unrecorded browser preference. Metadata compiler_h3.reduced_motion_variants maps accessibility.reduced_motion_variant references to source-bound definitions. Each animated element requires a complete explicit variant. Only opacity enter/exit tracks, or a bounded fixed frame of a governed analytic simulation, are supported. Original elements, claims, units, source/reasoning references and track intervals are not replaced. Other moving families are rejected. The original input fingerprint, selected variant, frozen samples and effective document fingerprint are recorded. Content/learning equivalence still requires domain validation.

## H3-004 — Isolated production typesetting

Production equations use a fresh Python child, no shell, isolated interpreter flags, controlled locale/config/cache/thread environment, bounded wall/CPU/memory/file output, and process-group cleanup. This is lifecycle/resource isolation, not a hostile-code or network sandbox. Keys bind actual compiler Python bytes, interpreter, selected backend dependency files, native backend binaries, packaged math fonts and fixed environment controls. Timestamps and absolute paths are excluded from semantic identity. Hashes do not redistribute font files. Cross-host changes invalidate cache/revalidation rather than being called deterministic success. Full Node dependency/OS provenance is outside this receipt.

## H3-005 — Adoption and remaining boundaries

Default checked source CLI emits the H3 envelope. The real-render entry requires H3 source revalidation as well as its existing pinned dependency/typecheck, discovery, media/log/artifact checks. Historical H1/H2 source diagnostic APIs do not acquire release authorization. Full-frame layer checks are not paint checks; a browser test bridge is not React or Remotion. Exact dependencies, real Remotion, audio/video frames, operational sandboxing and real-book learning/game acceptance remain separately open until actual evidence exists.
