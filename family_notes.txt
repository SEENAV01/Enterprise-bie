3D layer of the showing engine (fam-3d) — notes for the merge and for plan writers
=================================================================================

What it is
----------
A 3D layer the scene plan controls. A 3D model is a parametric procedural model drawn by code from three.js primitives
(the toolbox's pinned three 0.186.1, MIT; no downloaded art). It is described as a flat list of nodes by pure code
(engine/three/scene3d.mjs + kinds_*.mjs), so the same parameters and time always give the same description and the same
pixels; layer3d.mjs draws that description with three.js. A plan uses a model in two ways:
  - a scene's place:  scene field  world3d: {model, p, steps, cam3d, id (default "world3d"), enter}
                      a backdrop under the SVG people, things and words (z 0, fills the stage); never "the thing shown"
  - a thing:          item step whose thing is {model, p}, with id, x, y, w, h (default its manifest size), s, z, t0, t1,
                      enter (default fade), keys, steps, cam3d
Steps [{t, p, d}] change parameters on a cue word; numbers glide over d seconds (default 0.8, 0 jumps), choices and
bools switch on the word. cam3d [{t, d, angle, height, dist, tx, ty, tz, fov, spin}] moves the 3D camera (glides d s,
default 1.2; spin keeps turning, degrees per second). Processes (belt, cranes, traffic, smoke, rain, goods on routes)
move as a pure function of time since the model appeared.
at {of, spot, dx, dy, when} puts a person, text, mark, glow or item at a model's spot (screen position after its camera,
read at `when`, default when the element appears; `of` may be left out when the scene has one model; the model must
come before the step). Such elements carry "on": <model id>.

Checks (compiler + box rule)
----------------------------
Every parameter and step parameter against models3d.json (type, range, choice, unknown name), step fields (t, p, d),
cam3d fields and ranges, the kind's own checks (globe regions), at (model of the scene, known spot, seen by the camera),
a model never inside a group/hold/bubble/give, two models with one id. Box rule: a world3d is a backdrop (not "the
thing shown"); its parts are reserved zones measured at every half second (they move with its camera); a model item
is a thing whose box is its drawn parts after its camera; elements placed at a model's spot ("on") may label that
model and its zones. Spots, boxes and zones come from the engine's own description (tools/model3d_measure.mjs, one
Node call per batch, cached).

Render
------
render.needs_3d(spec) picks engine3d.html (build.mjs --engine3d: engine3d.mjs = engine.mjs + layer3d.mjs + three) only
for a spec with a model3d element; plain specs keep engine.js, which imports no three.js (test reads the import graph)
and draws 2D frames as the very same SVG string as before. A 3D frame is layers: SVG (background + parts below), the
WebGL canvas (one model: the canvas itself with its fade as opacity; two or more: copies, one per layer), SVG above
(+ foreground, kicker, subtitles). One WebGL renderer at the frame size, drawn once per frame inside the model's
rectangle after the 2D camera; geometries/materials cached; nodes sharing both drawn as one InstancedMesh. No PNG.
Same frame twice = same bytes (tested).

Measured speed (this 2-core cloud machine, 1280x720, whole MP4 path: draw + capture + encode, SwiftShader, MSAA on)
  plain 2D scene 0.082 s/frame · 3D factory 0.222 · 3D port 0.255 · 3D city (night, heavy traffic, ~1000 nodes) 0.419
  setFrame alone: factory ~131 ms, city ~173-188 ms; JS description+build+draw calls ~8 ms; the rest is SwiftShader's
  raster (antialias off saves 20-30% but leaves jagged edges, so it stays on).

What is left / unsure
---------------------
- IMPLEMENTED, not yet INTEGRATED: no real chapter plan uses world3d yet (W2 plan workers come after the merge).
- Spots are read once (at `when`); a label does not follow a part while the camera moves (place labels after the move).
- The needs list's island, kitchen, mandi, godown, labour chowk, river town are flat 2D worlds (the 2D worlds builder);
  a 3D mandi/godown could reuse the farm and factory parts later.
- 3D frames cost ~3-5x a 2D frame; long 3D scenes should stay where depth teaches.
- Engine step tweening for saanche is the coordinator's work; model steps glide on their own (paramsAt in scene3d.mjs).
- Words never go into the 3D picture (all labels are SVG at spots), so Hindi shaping and the 36 px floor stay the
  engine's usual checks.
