## H3-R01 — Actual ink, content fit and repair: PARTIALLY ADDRESSED / OPEN

H3-001 exhaustively enumerates every integer frame within explicit work budgets. It models supported nested 2D individual transforms, opaque-layer convex intersections and viewport clipping. It rejects unsupported work budgets rather than sampling a false pass. Explicit intentional overlaps are source/reasoning-bound and appear in the receipt; they do not imply readability approval. Reveal clipping is conservative, and legitimate artistic crops can be rejected. There is no between-frame continuous-time, transparent-ink, 3D-camera or universal-shape claim.

H3-002 validates exact scene/manifest/target-bound measurements for every element/frame. It detects incomplete frames, browser errors, unresolved fonts, text and legend overflow, and text/equations below technical pixel floors. It does not rewrite explanations, silently shrink fonts or remove information. A tiny equation and a long map legend still pass source generation but correctly fail content-fit measurements. That is a remaining producer/layout problem detected by QA, not a fully repaired capability.

The final browser experiment measured **504 frames / 792 element-frame records** over **13 synthetic cases**. Ten positive content-fit expectations and three explicit negative expectations matched. It saved 39 selected screenshots, not screenshots of every frame. Layer envelopes matched independent Chromium bounding-box observations within the declared 0.15 px comparison tolerance. The experiment includes three-element standard and reduced scenes and nested scale/translation wrappers.

The browser executed generated TS with explicit React/Remotion API doubles, then actual Chromium DOM painting. This is not real React or Remotion. Caller-supplied observation hashes are integrity labels, not trusted attestations. No existing content-fit receipt can authorize release.

**Still needed:** actual Remotion frame/DOM evidence, a trustworthy producer-to-QA evidence link, within-owner text/legend collision detection, font and locale variability, dense-content layout repair or explicit upstream revision, contrast/occlusion/ink checks and preservation of teaching intent during repair. Current source/layout gates are not a substitute for these.

## H3-R02 — Specialized consumers and accessibility equivalence: PARTIALLY ADDRESSED / OPEN

H3 resolves explicit accessibility references into complete source-bound opacity replacements or a fixed frame of one of H2's analytic simulations. It records original/effective fingerprints and keeps element content, units, source refs, reasoning refs, and track intervals. Geometry changes, unknown registry fields and unsupported dynamic families are not silently accepted. The derivative drops a stale original fingerprint and computes a fresh one while retaining original identity in lineage.

The reduction is intentionally bounded. It does not prove equivalent learning: freezing a simulation can omit the temporal explanation, and an opacity alternative can still be insufficient for a learner. Missing semantic consumers (specialized camera/morph/trace/state/event/audio bindings), broader motion families, narration alignment, accessibility testing and upstream instructional alternatives remain open. No automatic “reduced motion accepted” declaration is made.

Parent timeout and process-group cleanup are exercised. Two separate real child runs produced identical equation geometry. Parent global Matplotlib configuration no longer leaks into this production path; historical in-process diagnostics remain unchanged.

Cache and source identities bind the interpreter, compiler/Scene-IR Python files, selected mathematical dependency and native binary contents, package versions, packaged math-font hashes and fixed controls. Absolute workspace paths and timestamps are not semantic identity. Changed identity blocks reuse/revalidation. No font files are distributed.

**Limits:** this is not a hostile-code, OS or network sandbox; the child remains a trusted-code execution boundary. Identity does not cover every OS/shared-library/browser fallback or the installed Node tree. Container policy, process concurrency/queue limits, browser isolation, asset network rules and complete pinned JS dependency provenance remain separate work. Hash records are not cryptographic publisher signatures. Conservative byte identity can invalidate otherwise compatible hosts and is not a claim of cross-host byte reproducibility.

## Findings during this batch and actual disposition

1. A first full regression exposed missing ancestor-lineage copies for four files first changed in H3. Exact H1 originals were restored from the H2 archive; no assertion or historical hash was relaxed.
2. Reduced-motion derivation initially carried the original fingerprint into a changed document. The implementation now preserves it as provenance but computes a fresh effective fingerprint; dedicated regressions cover this.
3. Early browser fixtures used labels beyond H2's legitimate 80-character map-label contract. Fixtures were corrected to bounded labels in the third legend column; compiler bounds were not weakened.
4. Measuring the layer itself revealed inline-SVG baseline overflow. H3's source wrapper now establishes a scoped flex viewport for SVG-root families, without hiding overflow or changing legacy emitter defaults/goldens.
5. Nested-motion browser QA initially interpreted outer transformed scroll extents as content overflow. Measurement now evaluates the content owner and excludes outer motion-wrapper scroll extents; independent bounds comparisons still cover the full transform chain.
6. Negative dense-text, undersized equation and legend overflow fixtures remain **expected rejections**, not fixed layout producers. Do not reinterpret their successful detection tests as repaired content.

Initial failures and partial runs are preserved under validation/comp_h3, indexed by VALIDATION_RUN_INDEX.json. Current source evidence is browser_run_005 and source_benchmark_001; earlier records are not current-host production receipts.
